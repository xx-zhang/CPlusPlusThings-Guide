# 18 · 零拷贝与实时安全体系

> **场景**：高带宽传感器（点云/图像）在 ROS2 里太慢、latency 抖动、回调里分配导致实时性崩。
> **挂靠**：元原则 1（零开销抽象的正面：别复制）· A3（布局/存储）· 13 是定性基础、本体系给实时量化纪律｜**学**：先补 13，再读本文件｜**记**：08 L1「危险信号」+ 本节必背

---

## 0 · 这个体系解决什么问题

机器人里最常见的一句话是：**"数据本身不大，但每次都在拷贝，带宽一高就崩"**。ROS2 给你两条路（都要懂机制才会用）：

```text
路径 A：intra-process（同进程）零拷贝
  同进程的 pub/sub 不经过 DDS 序列化，直接走"环形缓冲 + 元消息"（官方设计：rmw 的 IntraProcessManager）
  ⟹ 用 unique_ptr 发布/订阅时真正零拷贝（官方 demo 已验证：发布与订阅看到同一地址）
路径 B：loaned messages（rmw 层）
  由中间件"借出"一块内存，应用直接填充后归还 ⟹ 免去一次应用↔中间件拷贝
```

**核心认知：零拷贝不是默认的，是有条件的；跨进程要走共享内存中间件，且协议/字节序有代价衡量。**

## 1 · 核心原则

### 1.1 为什么"拷贝"在机器人里是问题（从 A3/13 推出）

```text
一次消息拷贝 = 读一遍写一遍内存 = 吃掉带宽和缓存行；大消息（图像 1MB+）一次拷贝 ~ 微秒级
在 100Hz 回调里：拷贝开销 × 频率 = 必须省的部分
```

**推论（实时纪律）**：**热路径（回调/控制环）里禁止**：

```text
· 堆分配（malloc 不定时；vector 扩容搬移 O(n)）——jitter 的主要来源
· 字符串构造/拼接（SSO 内的小字符串尚可，大的=分配）
· 日志格式化（RCLCPP_INFO("%s", ...) 这类会构造 string；用轻量格式化或不打）
· 深拷贝（string/容器复制）
```

### 1.2 intra-process 零拷贝的机制（这才叫"懂原理"）

```text
同进程 pub/sub 时，rmw 不走网络：
  发布 → IntraProcessManager 把消息放"发布者的环形缓冲"；
  订阅 → 从缓冲取"指向那份内存的指针"（元消息走中间件标记就绪）
⟹ 应用之间共享同一块内存 = 零拷贝
条件：发布用 unique_ptr（或正确 move），订阅用 unique_ptr；类型支持 loaned
     不同进程 → 需要共享内存中间件（如 Cyclone SHM / 特定 rmw）+ 对应配置
```

**唯一性原则**：消息对象一旦"借出/进入缓冲"，**应用不能再改它**——否则读到一半变了。（这就是为什么回调参数是 `const`。）

### 1.3 实时（RT）上下文：调度与锁的深水区（先知道有这层）

```text
· 实时线程：SCHED_FIFO/RR（高于普通线程优先级）；锁争抢 → 优先级反转（低优先级持锁挡住高优先级）
· 测量工具：cyclictest（延时抖动）/ 应用内记录"回调耗时"的 max/p99
· 目标是"最坏情况可预测"，不是平均快——所以"分配不定时"被禁止
```

## 2 · 知识点地图（离散点）

| 点 | 一句话关键 | 注意 |
| --- | --- | --- |
| 消息拷贝链路 | 应用→序列化(CDR)→传输→反序列化→应用 | 每段都可能复制；零拷贝省掉一段或多段 |
| intra-process | 同进程共享环形缓冲（1.2） | **不同进程不生效**；要配置 |
| loaned messages | 中间件借内存、应用填、归还 | rmw 支持才可用（Fast DDS/RMW 有 demo） |
| unique_ptr 发布 | 所有权转移 = 可零拷贝条件之一 | 别在发布后继续用消息 |
| 环形缓冲 SPSC | 一写一读的无锁队列（intra-process 底层形态） | 多写多读要 MPSC/加锁 |
| 对象池/预分配 | 热路径拿"池里的"避免 malloc | 池要线程安全或 per-thread |
| CDR 序列化 | 每个字段按对齐规则编码 | 大数组是拷贝热点；改设计同时减小消息 |
| 缓存局部性 | SoA/连续 vs 每次拷贝 | 13 已给 AoS/SoA |
| RT 调度 | SCHED_FIFO、优先级反转、cyclictest | 深水区，先知道存在 |
| 时钟 | `system_clock`（墙上时间）vs `steady_clock`（单调） | 周期控制用 steady；ROS 时间/sim 另说 |

## 3 · 决策流程：要不要做零拷贝

```text
Q1 消息多大、多频？带宽真的吃紧吗？
   （小消息 < 几 KB + 低速 → 别折腾，普通拷贝开销可忽略）
   是 → Q2 生产与消费同进程吗？
        ├─ 同进程 → 开启 intra-process + unique_ptr 发布（改动小、收益大）
        └─ 跨进程 → Q3 有共享内存中间件/loaned 支持吗？
                 ├─ 有 → 配置 + loaned（成本高，先 profile 证明收益）
                 └─ 无 → 优化序列化/降频/降分辨率（别硬上）
Q4 回调里还分配吗？
   └─ 是 → 先做"回调零分配"改造（1.1 清单）——这往往比零拷贝更值钱
```

**排序**（收益从高到低，别跳）：

```text
1. 回调零分配（先把 jitter 根除）——任何场景都该做
2. intra-process + unique_ptr（同进程的免费午餐）
3. SoA/布局/降拷贝（13 的手段）
4. loaned / 共享内存（最后，成本最高）
```

## 4 · 常见坑（AI / 初学者代码高频）

| 坑 | 症状/原因 | 修法 |
| --- | --- | --- |
| 以为零拷贝默认开 | 同进程也没省到 | 显式 unique_ptr + 配置 intra-process |
| 发布后还改消息 | 订阅者读到半改的 | 发布即交出所有权（const 语义） |
| 回调里 `vector` 扩容 | jitter（10 的扩容实测） | reserve 到上界；环形缓冲 |
| 回调里 `std::to_string`/拼接 | 分配 + 格式化 | 预分配 buffer / 轻量日志 |
| `shared_ptr` 传递大消息 | 控制块原子操作 + 可能拷贝 | 观察用 const&；真共享才 shared |
| 小消息做零拷贝 | 收益为负（复杂度 > 省掉的开销） | 先 profile（10/13 铁律） |
| 把"回调快"当"实时性好" | 平均快 ≠ 最坏可预测 | 测 max/p99（cyclictest/计时） |
| 忽略字节序/协议 | 跨架构不一致 | CDR 保证；自定义序列化要自测 |

## 5 · 实践关联（动手清单）

```bash
# ① 复现"回调里分配"的 jitter：10 万次新建 vector vs 复用（用事实说话）
g++ -std=c++17 -O2 -x c++ -o allocj - <<'EOF'
#include <vector>
#include <chrono>
#include <cstdio>
volatile int sink;
int main(){
  auto t0 = std::chrono::steady_clock::now();
  for (int i=0;i<100000;i++){ std::vector<int> v; v.push_back(i); sink = v[0]; }  // 每次分配
  auto t1 = std::chrono::steady_clock::now();
  std::vector<int> rv; rv.reserve(1);
  for (int i=0;i<100000;i++){ rv.clear(); rv.push_back(i); sink = rv[0]; }        // 复用
  auto t2 = std::chrono::steady_clock::now();
  auto us = [](auto a, auto b){ return std::chrono::duration_cast<std::chrono::microseconds>(b-a).count(); };
  std::printf("每次新建: %ld us   复用: %ld us\n", us(t0,t1), us(t1,t2));
}
EOF
./allocj   # 复用比每次新建快多少？答案以你的机器为准

# ② 观察 unique_ptr 发布语义：发布后源对象被置空（对照 16 所有权转移）
# ③ 计时 p99：采集 1000 次回调耗时，打印 max / p99（实时性的正确度量）
```

## 6 · 与全局的连接

- **元原则 1 / 3**：零拷配备份"别复制、别在运行期做编译期能做的事"。
- **13**：分配/布局/缓存是 18 的预备知识；**10** 扩容实测直接支撑"回调零分配"。
- **16**：unique_ptr 发布 = 所有权转移与零拷贝条件合一。
- **17**：回调纪律（短/非阻塞/不分配）是 18 在"执行器模型"里的落点。

## 7 · 自测三问

- **判定**：intra-process 零拷贝在「跨进程」场景下会自动生效吗？（不会——需要共享内存中间件/配置；同进程才默认走 ring buffer）
- **预测**：回调里每次 `std::vector<int> v; v.push_back(...)`，比预分配 + 复用慢多少？（数量级差异——自己跑 5-1 的实验）
- **构造**：写一个发布模型：`unique_ptr` 发布大消息 + 回调里零分配，用"地址一致"证明零拷贝、用 p99 证明低抖动。
