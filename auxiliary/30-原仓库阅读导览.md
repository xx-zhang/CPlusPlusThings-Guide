# 30 · 原仓库阅读导览（降低心智负担）

> **用途**：读 `CPlusPlusThings` 时**先看这份**，知道每个目录**讲什么 / 读哪几个文件 / 跳过什么 / 哪里有坑**。
> **数据来源**：本机实测（`g++ -std=c++17 -fsyntax-only` 逐文件），不是印象。
> **配套**：错误清单见 `06-仓库审计报告.md`；知识归属见 `07-场景体系总览.md`；本导览只解决"**怎么读、读哪些**"。

---

## 0 · 四个标记（先认这个）

```text
🏛 必读     —— 承重内容，跳过会缺前置
📖 选读     —— 有收获但可延后，按需读
⏭ 跳过     —— 重复或极小，读了浪费时间
⚠️ 已知坑   —— 有错误/依赖缺失/故意编译失败（下面 §3 逐个列）
```

**一条元规则**：这个仓库的**代码比解释可靠**（`06` 已实测证伪 33 条解释）。所以：**先跑代码，再读解释，对上账再信。**

## 3.4 · 本地修订记录（2026-09，仅改客观代码缺陷，**不改解释**）

> 原则：**只修"客观错误"（路径/缺失 API/访问控制），不重写解释**——解释的错误由 `06-仓库审计报告.md` 统一记载，
> 避免两处说法冲突（SSOT）。

| 修订 | 文件 | 内容 | 效果 |
| --- | --- | --- | --- |
| ① | `learn_class/.../smart_ptr/*.cpp`（4 个） | `../RAII/shape.h` → `../reference/shape.h` | 露出更深问题（见②） |
| ② | `learn_class/.../reference/shape.h` | 补 `enum class shape_type` + `create_shape()` + `virtual ~shape()` + `virtual print()`（三个派生类覆写） | 4 个示例从**编译失败→通过** |
| ③ | `basic_content/using/derived_base.cpp` | `private: int value` → `protected:` | 与 README 一致，编译通过 |
| ④ | `basic_content/func_pointer/README.md` | **新建**（原缺失 → 主 README 死链，`06 §4.2`） | 死链修复 |
| ⑤ | `smart_ptr/auto_scope.cpp` | 教学类 `auto_ptr` → `my_auto_ptr`（18 处） | 避免被误认为 `std::auto_ptr`（**也消除静态检查误报**）；内容不变 |

**结果**：`basic_content` 11→**10** 个失败（**全为故意演示**）；`learn_class` 13→**9** 个失败（余下为 boost 缺失/真错）。

**可重放**：上述 5 项修订已导出为补丁 `local-reading-fixes.patch`（仓库根目录，7 个文件 / 232 行）。
若你重新 clone 上游仓库，执行 `git apply local-reading-fixes.patch` 即可一键复原（已验证 `git apply --check` 通过）。
**注意**：只改上游**本地克隆**，不向 `Light-City/CPlusPlusThings` 提交。

**为什么 `auto_scope.cpp` 不按静态检查建议替换成 `unique_ptr`**：那个 `auto_ptr` 是**文件内自己写的教学类**（演示所有权转移语义），不是 `std::auto_ptr`；
按建议替换会**删掉整篇教学内容**。这是"工具要判断、不要盲从"的实例（`03` 约定一）。
