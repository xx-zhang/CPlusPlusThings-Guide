## 0 · 这个体系解决什么问题

你在自研或读别人的代码时最常撞见的三件事：

```cpp
// ① 循环引用 → 内存泄漏（两个 shared_ptr 互相指）
struct A { std::shared_ptr<B> b; };
struct B { std::shared_ptr<A> a; };

// ② enable_shared_from_this 崩了
auto n = std::make_shared<MyNode>();   // 必须这样创建
n->run_callback();                     // 内部 shared_from_this() 安全
MyNode stack_node;                     // ❌ 在栈上创建后调用 shared_from_this() → 抛 bad_weak_ptr / terminate

// ③ shared_ptr 的并发幻觉
// "shared_ptr 是线程安全的" → 错！只有控制块的引用计数是原子的，指向的对象不是
```

**核心认知：shared_ptr 管理两样东西——「对象」和「控制块」。两样的线程安全性不是一回事。**

---

## 1 · 核心原则

### 1.1 所有权三态（08 已有，这里展开到 ROS2 场景）

| 语义 | 类型 | ROS2 里长什么样 |
| --- | --- | --- |
| **独占** | `unique_ptr` / 值成员 | 你要把消息交给别人、自己不再用时（发布侧可 `unique_ptr` 发布，配合零拷贝 18） |
| **共享** | `shared_ptr` / `weak_ptr` | 节点、Publisher/Subscription 句柄、回调捕获、跨线程传递的消息——**ROS2 默认形态** |
| **借用** | `T*` / `T&` / `span` | 回调参数 `const Msg&`；必须由调用者保证生命周期 |

### 1.2 shared_ptr 的两个"线程安全"层次（最容易错）

```text
控制块（引用计数）：原子操作 → 多个线程同时拷贝/释放 shared_ptr 安全
   指向的对象：     完全不是线程安全的 → 两个线程同时读写 *p 仍是 data race（A2）
```

**推论**：跨线程传递消息用 `shared_ptr` 传递**所有权是安全的**；但两个线程**同时读同一个消息**，若消息本身无同步，仍是 UB——「共享所有权」不等于「共享读写」。

### 1.3 weak_ptr = 观察者（打破循环的唯一正解）

```text
weak_ptr 不参与引用计数 → 指向的对象可能已释放 → 用前必须 .lock()（失败=已释放）
典型：缓存、回调捕获节点、观察者列表
```

**循环引用为什么是泄漏**：A 有 B、B 有 A ⟹ 引用计数永不为 0 ⟹ 析构永不被调（这和"崩溃"不同，是**静默泄漏**——08 反例档案该记一条）。

### 1.4 `enable_shared_from_this`：三句硬规则

```cpp
class MyNode : public std::enable_shared_from_this<MyNode> { ... };
```

1. **对象必须由 `shared_ptr` 管理**（`make_shared`）——栈上/裸 new 的对象调用 `shared_from_this()` ⟹ 抛 `std::bad_weak_ptr`。
2. **构造过程中（构造器里）调用** `shared_from_this()` ⟹ 同样抛（此时还没有 owner shared_ptr）。
3. 派生类里要写 `enable_shared_from_this<派生类>`（传自己的类型），否则基类版本 `this` 转回基类指针，控制块不匹配。

**为什么 rclcpp 必须这样**：`rclcpp::Node` 继承 `enable_shared_from_this<Node>`；`executor.add_node()` / 回调捕获节点经常要 `shared_from_this()`（官方 issue #726 证实：executor 对节点只保持**弱引用**，节点实际存活由你自己的 shared_ptr 决定）。

### 1.5 ROS2 里 shared_ptr 的典型使用点（照此阅读代码）

```cpp
// 发布侧：create_publisher 返回 Publisher::SharedPtr（共享句柄）
pub_ = this->create_publisher<Msg>("topic", 10);
// 订阅侧：回调收到 const Msg::SharedPtr（共享所有权，跨线程安全传递）
auto cb = [this](const Msg::SharedPtr msg){ process(*msg); };
// 生命周期：main 里 make_shared 创建节点 → 交给 executor → executor 持弱引用
rclcpp::spin(std::make_shared<MyNode>());
```

## 2 · 知识点地图（离散点）

| 点 | 一句话关键 | 注意 |
| --- | --- | --- |
| `make_shared` | 一次分配放对象+控制块（省一次 new） | 用 `make_shared` 别裸 `new shared_ptr<T>` |
| `use_count()` | 原子计数，**竞态下是近似值** | 别拿它做同步判断 |
| `get()` 裸指针 | **借用期纪律**：裸指针存活不能超过持有它的 shared_ptr | 存下来跨越了这个 → 悬垂 |
| 自定义 deleter | `shared_ptr<T>(new T, deleter)` 接管 RAII 对象（fd、句柄） | 给外部 API 用 |
| 别名构造（aliasing） | `shared_ptr<X>(p, &p->member)`：共享控制块、指到成员 | 避免整个对象复制 |
| `weak_ptr::lock()` | 原子地转回 shared_ptr；失败=已释放 | 比裸 `expired()+use_count()` 安全 |
| 循环引用 | 双方 shared ⟹ 泄漏 | 一方改 weak；或改结构（父持有子、子注回父指针） |
| `shared_from_this` | 见 1.4 三条硬规则 | ROS2 节点标配 |
| 返回/参数惯例 | 出参所有权转移→`shared_ptr` 或 `unique_ptr`；只观察→`const&` | 参考 1.1 表 |

## 3 · 决策流程：这段代码里该用哪种所有权

```text
问：这个对象的生命周期，代码里谁能回答？
 ├─ 正好一个"主人"，主人死了它就该死  → unique_ptr / 值成员
 ├─ 多个主人、最后一个死了它才死       → shared_ptr
 │      └─ 其中有人只是"借用/观察"     → 观察者用 weak_ptr（用前 lock）
 └─ 谁都不拥有、调用方保证活着         → 裸指针/引用/span（借用）
再问：跨线程吗？
 └─ 是 → 传 shared_ptr（所有权随引用计数安全转移），共享的读写仍需同步（1.2）
```

**循环出现了怎么办（三选一）**：

```text
① 语义上应该单向：改成"父持有 shared，子只持 weak/裸"
② 用 shared_from_this 注册回调，但捕获 weak 并在回调里 lock
③ 干脆拆结构（观察者/事件总线模式）
```

## 4 · 常见坑（AI / 初学者代码高频）

| 坑 | 症状/原因 | 修法 |
| --- | --- | --- |
| 循环引用 | 静默泄漏（不减内存也能搜到） | 一方 weak；或结构重构（1.1 决策） |
| 栈上对象调 `shared_from_this` | `bad_weak_ptr` / terminate | 必须 `make_shared` 创建 |
| 构造器里 `shared_from_this` | 同上（还没 owner） | 两段初始化：构造完再 `init()` |
| "shared_ptr 线程安全" | 对象仍可 race（1.2） | 数据同步用 mutex/atomic；shared_ptr 只管所有权 |
| `get()` 存下来跨生命周期 | 悬垂裸指针 | 需要长期借用→weak_ptr+lock；短期借用→确保持有者活着 |
| 回调捕获 `this` 裸指针 | 节点死了回调还跑 → 悬垂 | 回调捕获 `shared_from_this()`（记 1.4 前提） |
| `weak_ptr.expired()` 后裸用 | TOWS-between（检查后对象已释放） | 直接 `.lock()` 用返回值 |
| 大对象频繁 shared_ptr 拷贝 | 原子操作开销（控制块） | 用 `const&` 传递观察；确属共享才传值拷贝 |

## 5 · 实践关联（动手清单）

```bash
# ① 循环引用泄漏 vs weak 修复（自己跑，看析构打印次数）
g++ -std=c++17 -fsyntax-only -x c++ - <<'EOF'
#include <memory>
#include <cstdio>
struct B; 
struct A { std::shared_ptr<B> b; ~A(){ std::printf("~A\n"); } };
struct B { std::weak_ptr<A> a;   ~B(){ std::printf("~B\n"); } }; // 一方 weak
int main(){ auto a = std::make_shared<A>(); a->b = std::make_shared<B>(); a->b->a = a; }
EOF
# 用 ASan（LeakSanitizer）验证无泄漏
g++ -std=c++17 -g -fsanitize=address -x c++ - <<'EOF'
#include <memory>
struct B2; struct A2 { std::shared_ptr<B2> b; };
struct B2 { std::shared_ptr<A2> a; };   // 双方 shared → 泄漏
int main(){ auto a = std::make_shared<A2>(); a->b = std::make_shared<B2>(); a->b->a = a; }
EOF
./a.out   # → LeakSanitizer: detected memory leaks

# ② 复现 shared_from_this 两个陷阱（bad_weak_ptr）
# ③ 写一个节点生命周期的弱引用演示：executor 只持 weak（对照官方 issue #726）
```

## 7 · 自测三问

- **判定**：两个 `shared_ptr` 互相指，会怎样？（循环 → 析构不执行 → 静默泄漏；一方 weak 修复）
- **预测**：栈上对象调用 `shared_from_this()` 会发生什么？为什么 `make_shared` 创建就行？（`bad_weak_ptr`——因为控制块里没有 owner）
- **构造**：写一个「节点 → 订阅回调」的模型：节点 `make_shared` 创建、回调捕获 `shared_from_this()`、executor 持 weak，验证结束时不泄漏、回调运行时对象必然存活。
