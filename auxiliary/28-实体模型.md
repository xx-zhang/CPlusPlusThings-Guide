# 28 · 实体模型（C++ 世界里有哪些实体、怎么关联）

> **为什么需要这一篇**：读代码/读标准时遇到生僻术语（"完整对象""内存位置""值表示""子对象"），需要一张**本体表**来定位。
> 它也是四域分类的**名词版**：机制（A/T）回答"怎么运行"，实体（本篇）回答"世界里有什么"。
>
> **依据**：ISO C++ 标准术语（条款名稳定；**编号随草案版本变化**——C++23 起 `[intro.memory]`/`[intro.object]` 合并进 `[basic.memobj]`）。本文为**转述**，精确措辞请查标准原文。

---

## 1 · 标准自己的实体清单（权威锚点）

标准 `[basic.pre]` 直接给了一张清单：

```text
"An entity is a value, object, reference, structured binding, function,
 enumerator, type, class member, bit-field, template,
 template specialization, namespace, or pack."
```

**这 13 项就是 C++ 承认的"实体"**。注意两点：

1. **entity ≠ name**：实体是"东西"，名字是"指向东西的标签"。同一个实体可以有多个名字（别名/`using`），一个名字也可以在不同作用域指向不同实体。
2. **后面新增的项**（structured binding / pack / result binding）说明这张清单在演进——**实体层也在膨胀**，这是"框架可修订"的一个实例。

## 2 · 工程分类：七组实体（按"读代码用得上"重排）

| 组 | 实体 | 标准条款（名） | 与谁关联 | 在哪条 A/T 里被用 |
| --- | --- | --- | --- | --- |
| **① 翻译类** | 翻译单元、头文件、声明、定义、符号、链接性（外部/模块/内部/无）、ODR 可定义项 | `[basic.def.odr]` `[basic.link]` | 声明 —引入→ 名字；定义 —定义→ 实体 | **A1**·T6 |
| **② 名字类** | 标识符、限定名、名字空间、`using` 声明/指令、查找域 | `[basic.scope]` `[basic.lookup]` | 名字 —denotes→ 实体 | A4·**22 §1** |
| **③ 类型类** | 基本类型、类类型、枚举、引用、指针、数组、函数类型、成员指针、模板/偏特化/显式特化 | `[basic.types]` `[temp]` | 类型 —描述→ 对象/引用/函数 | **T8**·A4 |
| **④ 对象类** | 对象、子对象（基类/成员/数组元素）、完整对象、最派生对象、临时对象、位域 | `[intro.object]` `[class.mem]` | 对象 —包含→ 子对象 | **A3**·T2·**T12** |
| **⑤ 存储类** | 存储、存储期（自动/静态/线程/动态）、内存位置、字节、对齐 | `[basic.stc]` `[intro.memory]` | 对象 —占据→ 存储 | A3·11 |
| **⑥ 表示类** | 对象表示、值表示、填充位、值 | `[basic.types]` | 表示 —编码→ 值 | A3·A2 |
| **⑦ 运行类** | 线程、执行、调用帧、`this`、vptr/vtable、异常对象 | `[intro.multithread]` `[class.cdtor]` | （实现层，见 T11） | A2·T5·**T11**·11 |

**使用方式**：读到不认识的词 → 先归组 → 就知道它挂在哪条 A/T，以及该去哪一篇查。

## 3 · 五对最容易混的实体（专家级澄清）

### 3.1 存储 ⟷ 生命周期（同一块存储可以先后住两个对象）

```text
存储：一块内存（哪里、多大、对齐）        ← 由分配决定
生命周期：对象"活着"的区间               ← 由构造/析构界定
```

**关键**：`placement new` 允许在**同一存储**上终结旧对象、开始新对象。
⟹ 这就是 A3 为什么把两者列为**独立属性**；也是 `[basic.life]` 存在的原因。

### 3.2 对象 ⟷ 内存位置（data race 是按"内存位置"定义的！）

```text
对象：占据存储、有类型/生命周期
内存位置（[intro.memory]）：标量类型的对象，**或**「相邻非零宽位域的最大序列」
```

**关键**：并发规则说的是"两个线程访问同一**内存位置**、至少一个写 ⟹ data race"。**相邻位域被算作同一个内存位置**——这是位域在并发里特别危险的原因（两个线程改同结构体的不同位域 = 同一内存位置 = 竞争）。

### 3.3 完整对象 ⟷ 子对象 ⟷ 最派生对象（构造/析构顺序与 `dynamic_cast` 都靠它）

```text
完整对象：不是一个更大对象的子对象（如整块变量）
子对象：基类子对象 / 成员子对象 / 数组元素
最派生对象：构造/析构时"当前正在构建的那个层次"
```

**推论（串起 T5/T12）**：

- 构造顺序：基类 → 成员 → 自己；析构严格逆序（T12）。
- **构造/析构期间，虚函数派发到"当前层次"而非最派生** ⟹ 构造函数里调虚函数不派发（T5 的实用推论），本质就是"此时最派生对象还不是派生类"。

### 3.4 对象表示 ⟷ 值表示（为什么 `memcmp` 比对象是错的）

```text
对象表示（[basic.types]）：sizeof(T) 个 unsigned char
值表示：其中**参与表示值**的那些位
填充位：其余位（不属于值表示）
```

**推论**：`memcmp` 比较的是**对象表示**（含填充位），两个"相等"的值对象可能因填充位不同而 `memcmp` 不等 ⟹ **别用 `memcmp` 比较结构体**（除非常量初始化且无填充，且类型是 trivially copyable）。

### 3.5 声明 ⟷ 定义（ODR 的"定义"是一张清单）

```text
声明：把名字引入程序
定义：能定义/实现的那些声明 —— 标准明确列出可定义项：
      类类型、枚举类型、函数、变量、模板化实体、参数的默认实参、默认模板实参 等（[basic.def.odr]）
```

**推论**：`class A { static const int k = 7; };` 里 `k` 是**声明 + 初值**，不是定义 ⟹ 取地址立刻 `undefined reference`（T2 的 ODR 陷阱）。

## 4 · 编译期实体 ⟷ 运行期实体（对应 A4，中间靠两座桥）

```text
编译期实体（A4 上半）：名字、类型、模板、重载集、访问控制、常量表达式
        ↓ 桥一：符号（A1/T6）—— TU 之间靠符号名连接
运行期实体（A4 下半）：对象、值、线程、vtable 表项、异常对象、栈帧（T11）
```

**两座桥**：

| 桥 | 连接什么 | 出错时的现象 |
| --- | --- | --- |
| **符号 / 链接**（A1·T6） | 名字 → 其它 TU 的实体 | `undefined reference` / `multiple definition`（23 §1 决策树） |
| **ABI**（T11） | 编译期布局 → 真实机器 | 跨编译器/版本崩；跨 .so ODR 冲突（19） |

**读法**：任何"编译器说的"和"运行时发生的"对不上，先问是**哪座桥**出了问题。

## 6 · 自测三问

- **判定**：`placement new` 能"在同一块内存上换一个对象"——这利用了哪两个实体是**独立**的？（存储 vs 生命周期，A3 的核心）
- **预测**：两个线程分别写同一个结构体的**不同位域**，是 data race 吗？（是——相邻非零宽位域构成**同一内存位置**，`[intro.memory]`）
- **构造**：给你一个"用 `memcmp` 比较两个结构体是否相等"的实现，说明它为什么可能出错，并给出两个正确的替代方案（逐成员比较 / 定义 `operator==`）。
