# 04 · 学习路线图

> 14 课，按**公理和定理**组织（不按仓库目录组织）。
>
> 每课都有三层检查点（判定 / 预测 / 构造），对应 `03-学习方法与步骤.md` 第四节的判定标准。
>
> **每课 20~40 分钟。强烈建议分 2~3 周做，不要赶。**

## 使用方式

1. 找到你**当前最痛**的那一课，从它开始（不必从第 1 课开始）。
2. 每课按 `03` 的**六步实证法**走：定位 → 预测 → 实测 → 对账 → 反例 → 归档。
3. **三层检查点全过才算完成**，尤其是第 3 层「构造」。
4. 完成后在下面的进度表打勾，并写下你的反例。

## 第 1 课 · 翻译单元与链接

**对应**：A1 翻译单元公理 · T6 定义位置决定链接性

**为什么放第一**：AI 生成的 C++ 代码最常见的两类错误（`multiple definition` / `undefined reference`）100% 属于这一课。而且这一课建立的「符号」直觉，是后面所有课的地基。

**仓库章节**：`basic_content/extern` · `basic_content/static` · `basic_content/inline` · `basic_content/const`（第 3 节）

**核心原则**：
> 编译器一次只看到一个 TU。任何名字必须「全程序唯一，或被显式声明为可以有多份」。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 同一头文件里写 `int add(int,int){...}`，被两个 `.cpp` 包含，会发生什么？为什么？ |
| 预测 | 改成 `inline` / `static` / 放进匿名 namespace，三种改法的**链接行为分别是什么**？（提示：`inline` 合并成一份，`static` 各留一份） |
| 构造 | **自己设计一个实验**，证明「`inline` 是给链接器的指令，而不是给优化器的建议」。 |

**详细讲义**：`lessons/01-翻译单元与链接.md`

---

## 第 2 课 · 对象四元组与三把尺子

**对应**：A3 对象模型公理 · A1（链接性与存储期）

**为什么重要**：这是**整个框架的地基**。四元组（存储/生命周期/类型/值）和三把尺子（作用域/链接性/存储期）是你后面 12 课的「坐标系」。

**仓库章节**：`basic_content/static` · `basic_content/this` · `basic_content/struct_class` · `basic_content/using`

**核心原则**：
> 一个对象有四个彼此独立的属性；一个名字有三个彼此独立的维度。**`static` 的三个含义，就是它在三把尺子上各改了一格。**

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 函数内 `static int x`、文件级 `static int x`、类内 `static int x` —— 三者在**作用域/链接性/存储期**上分别是什么？ |
| 预测 | 如果把类内 `static int x` 改成类内 `static int x = 5;`（C++11），会怎样？（对比 C++17 的 `static inline`） |
| 构造 | 构造一个「`static` 是必要的」和「`static` 会引发 bug」的**最小对照实验**。 |

---

## 第 3 课 · UB 与优化器

**对应**：A2 抽象机公理 · 元原则 1（零开销抽象）

**为什么重要**：这是**唯一能解释「`-O0` 对、`-O2` 错」的理论**。CAE/EDA 代码跑得久、优化开得高，这一课直接决定你能不能定位这类 bug。

**仓库章节**：`basic_content/volatile` · `basic_content/pointer_refer`（悬垂）· `basic_content/union`（类型双关）

**核心原则**：
> UB 不是「结果随机」，是「程序在抽象机上没有定义」。优化器可以**假定它不发生**，据此重构整个程序。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | `int f(int x){ return x + 1 > x; }` 在 `-O2` 下编译成什么？为什么？ |
| 预测 | 加 `-fwrapv` 呢？改用 `unsigned` 呢？（提示：无符号溢出是**有定义**的，回绕） |
| 构造 | 写一个**在 `-O0` 和 `-O2` 下输出不同**的最小程序，并说出是哪个 UB 导致的。 |

---

## 第 4 课 · cv 限定符与 const-correctness

**对应**：T1 cv 限定是类型属性

**仓库章节**：`basic_content/const` · `basic_content/this` · `basic_content/explicit` · `basic_content/enum`

**核心原则**：
> `const` 修饰的是**类型的读权限**，不是「值不会变」。`const` 成员函数 = `const T* const this` ⟹ 这是 `mutable` 存在的唯一理由。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | `void f(const int)` 和 `void f(int)` 是重载吗？（不是——顶层 const 被忽略） |
| 预测 | 为什么 `const int n = rand();` 是合法的？`const` 和 `constexpr` 的本质区别是什么？ |
| 构造 | 构造一个场景，说明 **`const` 对象为什么调用不到非 const 成员函数**，以及 `mutable` 如何解决它。 |

---

## 第 5 课 · 引用、指针与生命周期延长

**对应**：T3 引用是别名

**仓库章节**：`basic_content/pointer_refer` · `learn_class/modern_cpp_30/reference`（`lifetime.cpp`）

**核心原则**：
> 引用是**别名**，没有独立身份。所以它必须初始化、不能重绑定、`sizeof` 等于被引用对象。**临时对象的生命周期延长只发生在「引用直接绑定到临时对象」这一种句型上。**

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | `sizeof(int&) == ?` `int& arr[3];` 合法吗？为什么？ |
| 预测 | `const auto& r = f().g();` 中临时对象活多久？（提示：延长的是最外层临时量，不是内部的） |
| 构造 | 构造**三种**「引用悬垂」的最小例子：返回局部引用、成员引用绑临时对象、lambda 捕获引用后异步使用。 |

---

## 第 6 课 · 值类别、拷贝与移动

**对应**：T4 拷贝 vs 移动 · A4（编译期分层）

**仓库章节**：`cpp2.0/cpp11/rvalue.cpp` · `cpp2.0/cpp11/move.cpp` · `learn_class/modern_cpp_30/reference`（`collapses.cpp` · `forward.cpp`）

**核心原则**：
> 移动 = 窃取资源，源对象进入「**有效但未指定**」状态。`std::move` **不移动任何东西**，它只是一个 `static_cast`。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 一个「有效但未指定」的 `std::string`，你能对它做什么？不能做什么？ |
| 预测 | `const std::string s; auto t = std::move(s);` 是移动还是拷贝？为什么？ |
| 构造 | 自己实现一个带堆内存的类，加上移动构造函数，用 `nm` / 汇编证明**移动比拷贝少了一次内存分配**。 |

---

## 第 7 课 · 特殊成员函数：rule of 0/3/5

**对应**：T4 · 元原则 2（显式优于隐式）

**仓库章节**：`cpp2.0/cpp11/default_delete.cpp` · `codingStyleIdioms/4_copy-swap` · `basic_content/abstract`

**核心原则**：
> **声明了析构函数 ⟹ 移动操作隐式被 `delete`（不是「不生成」），拷贝操作隐式生成（已弃用）。** 所以「只加一个虚析构」会让类悄悄失去移动能力。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 一个只有 `~T()` 的类，还有移动构造吗？拷贝构造呢？ |
| 预测 | `struct S { ~S(){} };` 和 `struct S { ~S() = default; };` 有什么不同？ |
| 构造 | 构造一个例子：加一个虚析构后，某个容器的操作从移动退化成拷贝（用计数器打印验证）。 |

---

## 第 8 课 · RAII 与异常安全

**对应**：A5 资源公理

**仓库章节**：`codingStyleIdioms/3_RAII` · `learn_class/modern_cpp_30/RAII`

**核心原则**：
> 资源绑到生命周期上，析构函数就是 `finally`——**而且是编译器强制的**（栈展开保证）。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 为什么 C++ 不需要 `finally`？为什么析构函数不能抛异常？ |
| 预测 | 构造函数抛异常时，**已构造完成的成员**会被析构吗？**没构造完的**呢？ |
| 构造 | 实现三种异常安全等级（基本 / 强 / 不抛）各一个例子；用 `noexcept` 让编译器帮你检查。 |

---

## 第 9 课 · 三种所有权与智能指针

**对应**：A5 · T4（所有权三态）

**仓库章节**：`learn_class/modern_cpp_30/smart_ptr` · `basic_content/abstract`（`enable_shared_from_this`）

**核心原则**：
> **默认用独占（值或 `unique_ptr`）。** `shared_ptr` 只在「多个所有者、寿命无法静态确定」时用。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 为什么 `unique_ptr` 零开销，而 `shared_ptr` 有原子引用计数？ |
| 预测 | 两个 `shared_ptr` 互相指向对方，会发生什么？`weak_ptr` 怎么解决？ |
| 构造 | 用 `weak_ptr` 实现一个缓存，并证明它**不会阻止对象析构**（析构时打印）。 |

## 第 10 课 · 类布局：sizeof / 对齐 / vptr / EBO / 多继承

**对应**：A3（存储与类型）

**⚠️ 这一课是仓库错误最集中的地方（见 `06`）。必须实测，不能信仓库。**

**仓库章节**：`basic_content/sizeof` · `basic_content/vptr_vtable` · `basic_content/union` · `basic_content/bit` · `basic_content/struct_class`

**核心原则**：
> 布局 = **基类子对象 + 成员（按声明顺序）+ 对齐填充**。有 N 个多态基类子对象就有 N 个 vptr。**空基类子对象可以 0 字节，成员子对象最小 1 字节。**

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | `class A{char a; int b;}; class B:A{short a; long b;}; sizeof(B) = ?`（实测 24，仓库说「16 或 24」） |
| 预测 | `class MA : public VA, public VB`（都多态）`sizeof(MA) = ?` 里面有几个 vptr？（实测 16，两个） |
| 构造 | 用 `offsetof` + `-fdump-lang-class=-` **画出**一个含虚继承的类的完整内存图，标出每个 vptr 的作用。 |

---

## 第 11 课 · 静态分派 vs 动态分派

**对应**：T5 分派三层 · A4 · 元原则 1

**仓库章节**：`basic_content/virtual` · `basic_content/abstract` · `basic_content/c_poly` · `basic_content/vptr_vtable`

**核心原则**：
> 分派三层：编译期重载 / 编译期模板 / 运行期虚函数。**虚函数的运行期成本恰好是「一个指针 + 一次间接跳转」，而且只要编译器能证明动态类型就能完全消除。**

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 为什么构造函数不能是 virtual？**在构造函数里调用虚函数会发生什么？**（仓库漏了这条，但实际代码高频踩） |
| 预测 | 给类加 `final` 后，`int f(S& s){ return s.v(); }` 的汇编会变吗？（会，实测完全消除） |
| 构造 | 用 `-O2 -S` 对比「实际对象 / 引用 / `final` 引用 / 多态容器」四种情况下的汇编，标出哪些被去虚化了。 |

## 第 12 课 · 模板：推导、特化、SFINAE

**对应**：A4（编译期分层）· 元原则 3（编译期优先）

**仓库章节**：`cpp2.0/cpp11/variadic` · `cpp2.0/cpp11/template_template.cpp` · `learn_class/modern_cpp_30/SFINAE` · `learn_class/modern_cpp_30/compilerpoly` · `learn_class/modern_cpp_30/compilercompute`

**核心原则**：
> 模板实例化在**编译期**完成 ⟹ 零运行期开销、编译慢、**必须 header-only**（因为实例化需要看到定义）。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 真把模板定义放 `.cpp` 会报什么错？怎么用**显式实例化**救回来？ |
| 预测 | 模板实例为什么是弱符号 `W`？为什么两个 TU 各实例化一份不会报错？ |
| 构造 | 用 `if constexpr` 把一段「运行期 `switch` 判断类型」的代码改写成编译期分派，对比汇编。 |

---

## 第 13 课 · 惯用法：copy-swap / pImpl / CRTP

**对应**：A5 · T5

**仓库章节**：`codingStyleIdioms/`（`1_classInitializers` / `2_enumclass` / `3_RAII` / `4_copy-swap` / `5_pImpl`）

**核心原则**：
> 惯用法不是「风格偏好」，它们是**公理的工程化封装**。copy-swap 是 A5（异常安全）的封装；pImpl 是 A1（编译依赖）+ A5 的封装；CRTP 是 T5（静态多态）的封装。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | copy-swap 为什么天然满足**强异常安全保证**？ |
| 预测 | pImpl 为什么能**减少编译依赖**？（提示：A1——不完整类型） |
| 构造 | 用 CRTP 实现静态多态，用汇编证明**没有任何间接跳转**（对比 `virtual` 版本）。 |

## 第 14 课 · 并发：内存模型与 happens-before

**对应**：A2 的并发版（data race 是 UB）

**仓库章节**：`concurrency/Threading_In_CPlusPlus` · `learn_class/modern_cpp_30/memorymodel_atomic` · `design_pattern/producer_consumer`

**核心原则**：
> C++11 起，**data race 是 UB**，不是「结果不确定」。并发正确性 = 建立 **happens-before** 关系。

**三层检查点**：

| 层 | 问题 |
| --- | --- |
| 判定 | 为什么 `volatile` 不能用于线程同步？（它不提供原子性，也不提供内存序） |
| 预测 | `condition_variable::wait` 为什么必须放在 `while` 循环里？（虚假唤醒） |
| 构造 | 写一个**有 data race** 的程序，用 `-fsanitize=thread` 抓出来，再用 `mutex` / `atomic` 各修一次，对比性能。 |

## 每课结束后请回到 `01` 做一件事

**把这一课的结论，重新用「公理 → 定理」的语言复述一遍。**

例：学完第 1 课，你应该能说：
> 「头文件能不能放定义，这个问题完全由 **A1** 决定。因为编译器看不到别的 TU，所以合并重复定义的活只能交给链接器；链接器靠 **强/弱符号** 区分；`inline` 就是**把符号标成弱符号**的那把钥匙（T6）。」

**能这样复述 = 知识挂在了骨架上。不能 = 还是一张孤立的卡片。**
