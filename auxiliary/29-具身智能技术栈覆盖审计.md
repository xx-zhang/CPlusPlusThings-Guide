> **方法**：克隆 9 个具身智能/机器人方向的主流开源仓库 → **自动扫描 C++ 特性使用频次** → 反向核实我们 00-28 的覆盖情况 → 得出**证据排序的缺口清单**。
>
> **地位**：本文件是**证据来源**；缺口台账的单一事实源仍是 `26 §1.4`（SSOT）。
> **一句话结论**：语言内核覆盖**良好**；缺的是**三个生态层**（数值/Eigen · Python 绑定 · 并行模型）。

## 4 · 三条校准结论（**数据推翻了我们的两条预设**）

### 4.1 C++17 是工业基线，C++20/23 仍是少数

```text
C++17：eigen · gtsam · ompl · pybind11 · rclcpp · ros2_control
C++20：mujoco          C++23：taskflow
```

⟹ 我们以 C++17 为主体、把 C++20/23 标为"新代码优先"的定位**是对的**。
`concepts/ranges/jthread/expected` 在工业代码里**尚未普及**（`requires` 的 9/9 命中含大量注释/文档误匹配），不应作为紧迫项。

### 4.2 缺口清单必须由实证排序——「协程」被证伪为低优先

我们原先按"未来 C++"把**协程/模块**列为"修订类缺口"。实测：**`co_await` 0 命中、`jthread` 0 命中**。
⟹ **协程的优先级从"待补"降为"非紧迫"**。这是"缺口也应当实测"的范例（反例：想象出来的缺口会误导投入）。

### 4.3 底层 C 风格不是"坏味道"，是**有契约的工具**

`raw new`（9/9，gtsam 578 文件）· `reinterpret_cast`（8/9）· `const_cast`（8/9）· `union`（8/9）· `setjmp`（4/9）
在高性能数值/物理引擎里**大量且有意图地**出现（对齐分配、SIMD 类型双关、与 C 互操作）。
⟹ 我们 `01 A2`/`22 §4` 的"危险信号"清单**判据正确**，但**语气需校准**：读这类代码时先问"它的契约是什么"，而不是直接判定为缺陷。**这也是审 AI 代码时的关键区分**：AI 写裸 `new` 往往是遗漏，Eigen 写裸 `new` 是为了对齐。

## 5 · 缺口清单（证据排序，供 `26 §1.4` 采用）

| 优先 | 缺口 | 证据 | 建议产物 |
| --- | --- | --- | --- |
| **高** | **Eigen 与数值线性代数体系** | 7/9 仓库重度使用（gtsam 853 文件引用） | 新分册：表达式模板/CRTP、固定 vs 动态尺寸、`Ref`/`Map`、对齐与别名、`noalias` |
| **高** | **Python↔C++ 绑定（pybind11）** | 5/9（gtsam 202 文件） | 新分册：绑定即"跨语言 ABI/所有权"（与 `19` 同源）、GIL、类型转换、生命周期 |
| **中高** | **并行模型**：OpenMP / TBB / `std::execution` | OpenMP 4/9 · TBB 2/9（taskflow 389 处） | 扩 `11`：并行 for / 任务图 / 数据流 vs 线程+锁 |
| **中** | **SIMD 落地** | 4/9（eigen 28 文件用 intrinsics） | 扩 `13 §2`：对齐、别名、自动向量化条件、intrinsics 入门 |
| **中** | **实时调度落地** | ros2_control 1/9，但实时是具身智能命脉（`21 §3` 已标高优先） | 扩 `18`：SCHED_FIFO、`mlockall`、优先级反转、WCET |
| 中低 | `dynamic_cast`/RTTI 实战 | 7/9（gtsam 155 文件） | 扩 `01 T5` 或 `22` |
| 低 | 属性 `[[nodiscard]]`/`[[no_unique_address]]`/`[[likely]]` | 0–3/9 | 扩 `01 A3`（EBO 的现代替代）与 `27` |
| **降级** | 协程 / jthread | **0 命中** | 保持"修订类"，不再列为待补 |

## 6 · 复现方式

```bash
# 1) 克隆
mkdir -p ~/ea-lab/repos && cd ~/ea-lab/repos
for r in ros2/rclcpp ros-controls/ros2_control libeigen/eigen borglab/gtsam \
         stack-of-tasks/pinocchio google-deepmind/mujoco ompl/ompl \
         taskflow/taskflow pybind/pybind11; do
  git clone -q --depth 1 "https://github.com/$r.git" "$(basename $r)"
done

# 2) 扫描（特性 → 使用它的仓库与文件数）
#    见本会话脚本：正则表 + os.walk（跳过 build/third_party）+ 按"仓库数"排序
#    注意：grep -E 里 "|" 才是交替，"\|" 是字面竖线（本轮踩过这个坑）

# 3) 反向核实我们的覆盖
grep -rlE "<特性>" --include='*.md' auxiliary/ | wc -l
```
