## 表 1 · 三把正交的尺子（⭐ 最重要）

仓库里 `static` 那篇之所以读着乱，就是因为它把这三个**互相独立**的维度混在一起当「`static` 的第四种用法」讲。

| 轴 | 回答的问题 | 取值 | 谁决定 |
| --- | --- | --- | --- |
| **作用域**<br>scope | 这个名字**在源码的哪些位置能被写出来** | 块 / 函数 / 类 / 命名空间 / 全局 | 编译器（纯文本可见性） |
| **链接性**<br>linkage | 这个名字**别的翻译单元能不能看见** | 外部 / 内部 / 无 | 编译器（写进 `.o` 的符号表） |
| **存储期**<br>storage duration | 这块**内存在哪里、活多久** | automatic / static / thread / dynamic | 编译器 + 链接器 + 运行时 |

### 关键：三者完全独立，可以自由组合

| 声明 | 作用域 | 链接性 | 存储期 |
| --- | --- | --- | --- |
| `void f(){ int x; }` | 块 | 无 | automatic（栈，出块即亡） |
| `void f(){ static int x; }` | **块** | **无** | **static**（活到程序结束） |
| `int g;`（文件级） | 文件 | **外部** | static |
| `static int g;`（文件级） | 文件 | **内部** | static |
| `extern int g;` | 文件 | 外部（**引用别处**） | — |
| `class C { static int m; };` | 类 | 外部（**定义在别处**） | static |

### `static` 的三个含义 = 三把尺子上各改一格

这是解开 `static` 全部困惑的钥匙。**`static` 不是「一个功能」，它是在三个不同位置各改了一格**：

| 写法 | 改的是哪一格 | 效果 | 一句话理由 |
| --- | --- | --- | --- |
| 函数内 `static int count;` | **存储期** automatic → static | 出函数不销毁，只初始化一次 | 「我想记住上次的值」 |
| 文件级 `static int g;` | **链接性** 外部 → 内部 | 别的 TU 看不见 | 「这是这个文件的私事」（等价于 C++ 的匿名 namespace） |
| 类内 `static int m;` | **归属** 对象 → 类 | 不属于任何对象，没有 `this` | 「这是整个类的，不是某个实例的」 |

### 常见混淆及正确拆解

| 困惑的说法 | 用尺子拆开 |
| --- | --- |
| 「`static` 变量只分配一次空间」 | 说的是**存储期**。对三种 `static` 都成立，但不是它的定义特征 |
| 「`static` 函数只能访问静态成员」 | 说的是**类内 `static` 成员函数**（没有 `this`，所以访问不到非静态成员）。这跟文件级 `static` 毫无关系 |
| 「头文件里不能加 `static`，会每个 TU 一份」 | 说的是**链接性**。确实每个 TU 一份——**这正是它和 `inline` 的区别**：`inline` 是「多份定义合并成一份」，`static` 是「各留各的」 |
| 「`const` 默认就是 `static`」 | 说的是**链接性**：C++ 里命名空间作用域的 `const` **隐式内部链接**（**C 里不是！**） |

## 表 2 · 对象四元组（⭐ 最重要）

| 属性 | 回答什么 | 谁能改它 | 出错时的症状 |
| --- | --- | --- | --- |
| **存储** storage | 在哪、多大、对齐多少 | 类型定义、`alignas`、placement new | `sizeof` 不对、读到垃圾、崩溃 |
| **生命周期** lifetime | 从什么时候活到什么时候 | 构造/析构、作用域、`new`/`delete` | 泄漏、重复释放、悬垂、崩在析构 |
| **类型** type | 这堆字节怎么解释、能调用什么 | 声明、`static_cast`、`reinterpret_cast` | 调到错的函数、走错分支、UB |
| **值** value | 里面装了什么 | 赋值、拷贝、移动 | 数据被意外共享/改掉、改了副本没改原件 |

> **审代码时的第一步**：看到一个 bug，先问「**这四个里，哪一个是错的？**」
> 这一步能把 90% 的模糊怀疑，压缩到四个具体方向之一。

### 一个例子说明四元组的独立性

```cpp
class Empty {};
class EBO   : Empty { int x; };   // 空类在"基类"位置
class NoEBO { Empty e; int x; };  // 空类在"成员"位置
```

```text
sizeof(Empty) = 1
sizeof(EBO)   = 4    ← 空基类被完全优化掉（EBO）
sizeof(NoEBO) = 8    ← 空成员不能优化，仍占 1 字节 + 3 字节填充
```

**同样是「一个空的类」，只因为它处在「基类子对象」还是「成员子对象」的位置，存储布局就不同。**
这说明「存储」是可以被独立操纵的属性——这正是 `compressed_pair`、`std::vector` 的 allocator 存储等一大堆库技巧的根源。

## 表 3 · 所有权三态（审代码最常用）

| 语义 | C++ 表达 | 谁负责释放 | 何时选它 |
| --- | --- | --- | --- |
| **独占所有权** | `unique_ptr<T>` / 值成员 `T m;` | 拥有者 | **默认选这个**。CAE/EDA 里 90% 的场景 |
| **共享所有权** | `shared_ptr<T>` / `weak_ptr` 观察 | 最后一个拥有者 | 只有确实「多个所有者、寿命无法静态确定」时 |
| **借用（不拥有）** | `T*` / `T&` / `std::span` / `string_view` | **没人**——调用者保证生命周期 | 函数参数 |

### 判断一段代码的所有权是否清晰，问三句

1. **谁负责释放？** 说不清 ⟹ 所有权不明确 ⟹ 泄漏或重复释放。
2. **借用的东西能活多久？** 如果「借用者」可能比「被借用者」活得久 ⟹ 悬垂。
3. **共享真的必要吗？** 大量 `shared_ptr` 通常是「没想清楚所有权」的信号（而且是原子引用计数的性能开销 + 循环引用风险）。

## 术语速查

### 链接性与符号

| 术语 | 含义 |
| --- | --- |
| **TU（translation unit，翻译单元）** | 一个 `.cpp` 加它所有 `#include` 的内容，预处理后的结果。**编译的基本单位** |
| **ODR（One Definition Rule）** | 一个名字在整个程序里只允许有一个定义（除 `inline`/模板等例外） |
| **外部链接 external linkage** | 别的 TU 能看见这个符号（默认情况） |
| **内部链接 internal linkage** | 只在当前 TU 可见：`static` 全局变量/函数、命名空间作用域的 `const`、匿名 namespace 的成员 |
| **无链接 no linkage** | 局部变量、局部类 |
| **弱符号 weak symbol** | 允许多个同名定义存在，链接器挑一个。`inline`/模板/`constexpr` 函数产生的就是它 |
| **ODR-use** | 「这个实体被用到了，需要它的**定义**（地址）」——取地址、绑引用、`sizeof`（不取地址时不 odr-use） |

### 对象模型

| 术语 | 含义 |
| --- | --- |
| **POD / trivially copyable** | 可以安全地 `memcpy` 的类型（C++20 用 `std::is_trivially_copyable` 判） |
| **standard-layout** | 布局受标准约束的类型（可以安全地与 C 互操作） |
| **vptr** | 多态对象里指向虚表的隐藏指针（**是个实现细节，标准没规定**） |
| **vtable** | 每个多态类一张的函数指针表（**实现细节**） |
| **EBO（Empty Base Optimization）** | 空基类子对象占 0 字节 |
| **active member** | `union` 当前「活着」的那个成员 |
| **object representation** | 对象的字节表示（`unsigned char[]` 可以合法地看它） |
| **value representation** | 决定值的那些比特 |

### 类型与值

| 术语 | 含义 |
| --- | --- |
| **cv-qualifier** | `const` / `volatile` |
| **顶层 const** | 对象本身是 const（`int* const`、`const int`）。**函数参数上的顶层 const 会被忽略** |
| **底层 const** | 指向的对象是 const（`const int*`） |
| **值类别 value category** | 左值 lvalue / 将亡值 xvalue / 纯右值 prvalue；**是表达式的属性，不是变量的属性** |
| **转发引用 forwarding reference** | `T&&` 且 `T` 是被推导的模板参数 ⟹ 可绑定左值也可绑定右值 |
| **引用折叠 reference collapsing** | 模板推导期把 `X& &`→`X&`、`X&& &&`→`X&&` 等简化 |
| **decay** | 数组→指针、函数→函数指针、去掉 cv |

### UB 与优化

| 术语 | 含义 |
| --- | --- |
| **抽象机 abstract machine** | 标准定义语义的那台假想机器 |
| **as-if 规则** | 优化器可以任意改代码，只要**不触发 UB 时**可观测行为不变 |
| **UB（undefined behavior）** | 程序在这台抽象机上**没有行为定义**（不是「结果随机」） |
| **未指定行为 unspecified** | 实现必须选一种行为，但不告诉你是哪种（如函数参数求值顺序） |
| **实现定义 implementation-defined** | 实现必须选一种行为**并写在文档里**（如 `sizeof(int)`） |
| **strict aliasing** | 编译器假定不同类型（严格说：不兼容类型）的指针不会指向同一块内存。违反 ⟹ UB |
| **happens-before** | 并发里的偏序关系。没有它 + 至少一个写 ⟹ data race ⟹ UB |

## `nm` 符号类型速查表

跑 `nm -C xxx.o` 时看到的字母，是**最快判断链接性问题的工具**。

| 字母 | 含义 | 出现在哪 | 能不能重名 |
| --- | --- | --- | --- |
| `T` / `t` | 代码段符号（函数） | 大写 = 全局（外部链接）<br>小写 = 局部（内部链接） | 大写**不能**重名 |
| `W` / `w` | 弱符号 | `inline` 函数、模板实例、`constexpr` 函数、类内成员函数 | **可以**重名，链接器合并 |
| `R` / `r` | 只读数据段 | 大写 = 全局（如 C 的 `const int c`）<br>小写 = 局部（如 **C++ 的 `const int c`**） | 大写不能重名 |
| `D` / `d` | 已初始化数据段 | 同上大小写规则 | 大写不能重名 |
| `B` / `b` | 未初始化数据段（BSS） | 同上 | 大写不能重名 |
| `U` | **未定义引用**（需要链接器去找） | 只声明没定义的东西 | — |
| `u` | **唯一全局符号**（GNU `STB_GNU_UNIQUE`） | **C++17 `inline` 变量**、函数局部 `static`（在 `-fno-gnu-unique` 或部分编译器上退化为 `b`/`d`） | 可以重名，且**连 `dlopen` 进来的多个 .so 也共用同一份** |
| `V` / `v` | 弱对象 | 弱数据定义（较少见，与 `u` 不同） | 可以重名 |

> **别把 `u` 当成 `U`。**`u`（小写）= 唯一全局符号，是**已定义**的；`U`（大写）= 未定义引用，是**需要链接器去找**的。实测：C++17 `inline std::string g_name;` ⟹ `nm -C` 显示 `u g_name[abi:cxx11]`。
>
> **`inline` 函数是 `W`（弱符号），`inline` 变量是 `u`（唯一全局符号）——两者不是同一种符号类型。**

### 看到链接错误时的速查决策树

```text
undefined reference to `X'          → X 在别处只声明没定义，或类型不匹配
    ├─ 是 template？      → 模板定义没在头文件里（模板必须 visible 才能实例化）
    ├─ 是 static 成员？   → 类外定义忘了写，或在多个 .cpp 写了（后者报重定义）
    ├─ 是 static const int？ → 类内初始化只是"给值"，odr-use 时需要类外定义
    └─ 是 extern "C" 相关问题？ → 检查函数是否有 C 链接（见 06 的 extern 条目）

multiple definition of `X'          → 同一个强符号有两个定义
    ├─ 头文件里有普通函数/全局变量定义 → 加 inline / 改 static / 移到 .cpp
    ├─ C 和 C++ 的 const 混用        → C 的 const 是外部链接！
    └─ 忘了 #pragma once / include guard
```

## 实测环境与可复现性声明

本目录所有实测结论基于：

```text
g++ 14.2.0 (Debian 14.2.0-19)
clang 19.1.7 (Debian)
x86-64 Linux, Itanium C++ ABI
```

**凡是涉及「布局、偏移、`sizeof`、虚表内容、汇编」的结论都是 ABI 相关的。**
换编译器（尤其 MSVC）、换平台（尤其 32 位）、换标准版本都可能不同——`05-实验工具箱.md` 里给了重测命令。

**凡是涉及「语言规则」的结论（ODR、链接性、UB、值类别）在所有符合标准的实现上都成立。**
