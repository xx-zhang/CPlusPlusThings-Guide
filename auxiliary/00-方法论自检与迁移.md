# 00 · 方法论自检与迁移

> 回答三件事：**① 这套「公理/定理」到底是从哪个角度推出来的？② 怎样保证可推敲、可自验、后面不互相打脸？③ 生活/工作里怎么把这套底层思考延申出去？**
>
> 本文件是对 `01` 第 0.5 层的**加压自检**，不是再堆一套公理。读完应能判断：哪些能当推理引擎用，哪些只是教学标签。

## 1 · 推导角度：不是「数学公理」，是「三源对齐」

如果把 A1–A5 当成希尔伯特式公理（从几条原始命题推出全部定理），**一定牵强**——C++ 标准本身就不是形式完备系统，而且 A5 是推论、A2 定义在 A3 上。

**真正的推导角度是三源对齐**（三条必须能对上，对不上就是缺口或约定）：

```text
源 α  标准的正式模型     ISO C++ 抽象机 + 对象 + 翻译单元 + 类型系统
源 β  设计动机           Stroustrup：零开销、分离编译、值语义、C 兼容
源 γ  可观测仪器         编译器/链接器/sanitizer/汇编（本机 g++14.2 / clang19）
```

| 模型 | 主要对齐哪一源 | 一句话 |
| --- | --- | --- |
| A1 翻译 | α 的 TU/ODR + β 的分离编译 | 编译器一次只见一个预处理后的 `.cpp` |
| A3 对象 | α 的 object/lifetime/type/value | 世界里有什么 |
| A2 抽象机 | α 的 abstract machine + β 的 as-if | **跑在 A3 世界上的语义引擎**；UB = 某状态无定义 |
| A4 分层 | α 的编译期名字/类型 + β 的「能编就编」 | 何时决定：编译期 vs 运行期 |
| A5 资源 | **不是独立源**，由 A3 + 「栈展开必析构」推出 | RAII = 工程定理 |

**自验口令**：任何一条「定理」，必须能回答——

```text
1. 它对齐 α/β/γ 的哪一条？（对不上 → 可能是约定，标到 D5/约定域）
2. 我怎样证伪它？（给不出实验/条款 → 不是本框架的定理）
3. 它的失效前提是什么？（给不出前提 → 后面必打脸）
```

## 2 · 可推敲结构：世界 / 语义 / 翻译 / 时机

把五条**重新排成角色**，牵强感就会消失：

```text
         ┌──────────── 编译期 ────────────┐
         │ A1 翻译：程序怎么进来           │
         │ A4 时机：哪些事在运行前就定死   │
         └──────────────┬─────────────────┘
                        ▼ 生成
         ┌──────────── 运行期 ────────────┐
         │ A3 世界：对象 = 存储·寿命·类型·值 │
         │ A2 语义：抽象机在这个世界上迁移   │
         │     UB = 世界某状态没有迁移规则   │
         └──────────────┬─────────────────┘
                        ▼ 推出
                   A5 资源/RAII
```

这不是五兄弟，是 **「2 组 2 个 + 1 条推论」**。生活/工作里同一张图也成立：

| C++ | 生活 / 工作对应 |
| --- | --- |
| A3 世界 | **本体**：这件事里真正存在的实体是什么（角色、资产、状态、约束） |
| A2 语义 | **规则**：这些实体允许怎样变化；越界会发生什么（「未定义」= 组织没规定） |
| A1 翻译 | **通道**：信息怎么进来（文档、会议、接口、口头约定）——通道一次只看见局部 |
| A4 时机 | **何时锁定**：哪些必须事先定死，哪些可以运行时再定 |
| A5 资源 | **收尾**：谁获取谁释放；异常/失败路径上收尾是否被强制 |

## 3 · 自验协议（每条 A/T 过三关，过不了就降级）

| 关 | 问 | 过关标准 |
| --- | --- | --- |
| **可追溯** | 标准哪一概念，或 D1–D5 哪一条？ | 写得出名字，不是「感觉应该」 |
| **可证伪** | 一行命令能打脸吗？ | `g++`/`nm`/`-fsanitize`/`-S` 之一 |
| **有前提** | 什么条件下这句话不成立？ | 写进 08 记忆卡「失效前提」 |

**本框架已通过的自验（抽样，完整见 08 §3.2）**：A1（`inline`→`W`、两 TU 的 `const`）、A2（`-O2` 把 `x+1>x` 当恒真、data race）、A3（sizeof 不重排、多 vptr）、A4（`final` 去虚化）、A5（noexcept 里 throw → terminate）。

## 4 · 内部张力清单（不是「没有矛盾」，是「已标明前提」）

后面学到「打脸」时，先查这张表——**多数不是体系崩了，是忘了前提**。

| 张力 | 看起来矛盾 | 化解（前提） | 状态 |
| --- | --- | --- | --- |
| T4「拷贝=复制」vs 返回局部对象没拷贝 | 移动/拷贝没发生 | **拷贝消除**（C++17 起部分强制）；`return v;` 不要 `move` | ⚠️ T4 表述不完整，见 §5 缺口 |
| T5「虚函数必间接跳」vs `final` 变成 `movl $3` | 没跳 | **动态类型可证明时去虚化**；T5 的成本是「证明不了时」 | ✅ 已写进 T5 |
| A5「析构=finally」vs `-fno-exceptions` | 没有栈展开 | RAII **不依赖异常**也能工作；无异常时只剩正常路径析构 | ⚠️ 09/15 提过，公理层没写清 |
| A1「一次一个 TU」vs C++20 模块 | 模块可见性不同 | **模块会修订 A1 的实现**，不是推翻「分离编译」动机 | ✅ 已标在 0.5.4 / 01 附 |
| 「引用不能为空」vs 解引用空指针再绑定 | 引用空了 | 那是 **UB（A2）**，不是引用语义允许为空 | ⚠️ 仓库 pointer_refer 讲过，框架没单列 |
| A2「UB 整程序无意义」vs sanitizer 还能报某一行 | 好像只坏一行 | sanitizer 是**实现的诊断**，不是标准恢复了定义 | ✅ 工具 ≠ 语义 |
| 「inline 建议内联」vs `-O2` 不写 inline 也内联 | 关键字没用 | `inline` 主职是 **ODR（A1）**，内联是优化器的事 | ✅ 已纠正 |

> **自检结论**：体系**没有隐藏的逻辑环**；真正的风险是「把有前提的定理当成无条件口号」。08 记忆卡必须写「失效前提」就是为这个。

## 5 · 语言内核仍缺的、后面真会撞上的块（诚实缺口）

> ⚠️ **本表已降级为历史记录，不再维护**。活台账（单一事实源）在 **`26 §1.4`**（已闭合 8 项 / 仍缺 6 项）。
> **原因（2026-09 加固）**：同一批缺口在两个文件里各写一份口径 ⇒ `00` 说“仍缺”、`26` 说“已闭合”，直接矛盾。
> **规则（SSOT）**：**同一事实只在一处维护，别处只引用。** 活台账归 `26 §1.4`；实测数字归 `08 §3.2`。

下面这张表保留下来，是因为它记录了**当时自认的缺口**——对照 `26 §1.4` 可以看出哪几项已经升成一等定理（T8-T12）。

| 缺口 | 挂靠 | 为什么后面会撞 | 优先级（对照你的目标） |
| --- | --- | --- | --- |
| **求值顺序 / sequenced-before** | A2 的「时间」 | `i=i++`、函数实参顺序、线程里 happens-before 的单线程原型 | 中（审代码会遇到） |
| **名字查找 + 两阶段查找 + ADL** | A4 的「名字」 | 模板报错天书、`operator<<` 找不到、为什么这个重载被选中 | **高**（读模板/ROS2 API） |
| **初始化规则动物园** | A3 | `= {}` / `()` / NSDMI / 聚合 / 引用绑定 行为不同 | 高（AI 代码初始化经常错） |
| **拷贝消除 vs T4** | T4 补前提 | 返回值、C++17 强制省略构造 | 中 |
| **不完整类型** | A1+A3 | `unique_ptr` 析构要完整类型、pImpl、delete 不完整 | 高（pImpl/ROS2 头文件） |
| **未指定 / 未定义 / 实现定义 三分** | A2 | 把 unspecified 当成 UB 会过度恐慌 | 中（02 有词条，未升成支柱） |
| **模块 / 协程** | 修订 A1 / A5 | 「未来 C++」会改实现，不改动机 | 低（未用到再补） |
| **DRE / Events Executor** | 17 的未来形态 | 你说的「未来 ROS2」 | 低（TODO 已挂） |

**判断标准**：缺口「高」= 不补的话，**用现有 A/T 推会漏步骤**；「中」= 能推但费劲；「低」= 四域里「其它系统」，先分类即可。

**对你「读改审 AI 代码 + 对标 ROS2」：现在这套驾驭能力够用。** 高优先级三块（名字查找、初始化、不完整类型）是**应用时按需补课**，不是推倒重来。

## 6 · 生活 / 工作里怎么延申这套底层思考

> ⚠️ **本节的四问版只够「描述系统」，不够「解释并跟进系统」**（学习者 2026-09 的准确批判）。
> 缺的是 **目标 / 激励 / 反馈** 三块，以及「未规定区由谁填充」——**最要命的是本节丢掉了 γ 源（反馈/度量），因此无法自验**。
> **进入新领域/新组织/新系统请用 [`20-领域进入方法论.md`](20-领域进入方法论.md)**（七层 + 五问 + 三补 + 8 条检验 + 七步跟进）；本节保留作**轻量场景**用。
> 另外：本节四个问题的编号（①→A3 ②→A2 ③→A1）与公理编号倒着跳，20 里按**认知顺序**重排并解释了两种顺序的分工。

不要另造一套人生公理。**复用同一张角色图 + 同一套自验协议。**

### 6.1 四个问题（碰到任何复杂事先问）

```text
① 世界：这里真正存在的实体是什么？（人、状态、钱、接口、约束）     ← A3
② 规则：这些实体允许怎样变？越界谁都不认账的是什么？             ← A2（组织里的「UB」= 未规定）
③ 通道：我此刻看见的是全貌还是一个「翻译单元」？                   ← A1（会议纪要、接口文档都是局部）
④ 时机：哪些必须事先锁死，哪些可以现场定？                         ← A4
然后：失败路径上谁负责收尾？有没有被强制？                         ← A5
```

### 6.2 工作中的直接用法

| 场景 | 怎么用 |
| --- | --- |
| **审一份设计 / 一份 PR** | 先分类：机制（必须对）/ 约定（风格）/ 实现细节（可测）/ 另一领域（别装懂）。只对「机制」花大力气推演。 |
| **排查「流程偶尔出错」** | 先找有没有「未规定的状态」（组织版 UB），再找「通道一次只看见局部」（A1：两个组各写一份配置）。 |
| **学一个新系统（ROS2、某仿真器、某团队规范）** | 先找它的 D（它为什么这样），再投影 3～5 个模型，标约定，不要从 95 条 FAQ 背起。 |
| **带人 / 自己做笔记** | 每条知识强制三行：原则 / **前提** / 反例。没有前提的「原则」后面必打脸。 |
| **决策卡住** | 问「这是定理还是定义」：能从已有约束推出来的就推；推不出的标成约定，选一个并写清代价。 |

### 6.3 反模式（这套思考最容易走歪的地方）

```text
· 收藏公理：只增加支柱，不拿真实问题证伪 → 知识收藏癖（你已明确反对）
· 口号化：丢掉「失效前提」，T4/T5 那种张力就会变成「体系矛盾」
· 领域越权：用 C++ 模型去「证明」产品该怎么定价 → 那是另一套系统
· 仪器崇拜：把一次 g++ -O2 的输出当成标准 → 实然 ≠ 必然（换 clang/MSVC 要重测）
```

### 6.4 一条可带走的元规则

> **先画「世界」和「规则」，再画「我看见的局部」和「何时锁定」。**
> 能推的当定理用；推不动的标约定；测得出的当仪器；测不出的当未知，不要假装成公理。

这就是 0.5.5 五步法在生活/工作里的压缩版。C++ 只是第一个练功场。
