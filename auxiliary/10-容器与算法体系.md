## 0 · 这个体系解决什么问题

- 用 `list` 当 vector 用（随机访问 O(n)）
- 往容器里塞**复制昂贵又不给移动**的类 → 每次扩容全拷贝（已实测：15 次复制）
- 边遍历边 `erase` → 迭代器失效崩溃
- 复杂度靠背 → 记不住，因为没有「为什么」

**记住原则就行，别背复杂度表**：容器的复杂度是它的**数据结构**（布局，A3）直接决定的——看到布局，复杂度自己跑出来。

## 1 · 核心原则

### 1.1 容器 = 「所有权 + 布局 + 访问策略」三件事的组合（A3 + A5）

```text
所有权：容器拥有元素（名字/生命周期归它管）→ 值语义，拷贝容器=深拷贝每个元素
布局：  vector=连续一段内存  list=双向链表  map=红黑树  unordered=哈希桶   ← 复杂度从这里来
访问：  operator[] 都是 O(1)（连续）或基于搜索（树 O(log n)、哈希 均摊 O(1)）
```

**看布局 → 推复杂度**：连续内存 ⟹ 随机访问 O(1)、中间插入 O(n)（要搬）;链表 ⟹ 中间插入 O(1)（要找到位置 O(n)、缓存差）;树/哈希 ⟹ 按键查找。

### 1.2 move 是容器扩容的燃料（T4）

`vector` 满员再插 → 分配到新内存 → **把老元素搬到新家**。搬用移动还是拷贝，由移动构造是否 `noexcept` 决定（1.2 you already know, 09）——**这是它选 move 还是 copy 的开关**。

### 1.3 迭代器失效规则 = 布局的直接推论（不用背，用「引用会不会失效」推导）

> 迭代器本质是「指向元素存储的指针」。**元素搬了家或没了，指向它的迭代器就失效**。

```text
vector： 扩容 ⟹ 所有迭代器/引用失效；erase 中间 ⟹ 其后全部失效
deque：  头尾操作不影响其它元素，但迭代器可能因分块结构失效（保守处理：全失效）
list/forward_list： 插入删除**不影响其它元素**的迭代器（只有被删的那个失效）
set/map：插入删除不影响其它迭代器（树节点独立分配）
unordered_*：rehash 时全部失效；其它插入不失效（保守：erase 后仍可用，但别依赖）
```

**够用就行：vector 一扩容全废，list/树 只废被删的。**

### 1.4 算法与容器解耦

算法（`<algorithm>`）不知道容器的存在，只认**迭代器**。好处：同一套 `sort` 能用在 array/vector/deque/ 原生数组上。代价：过程式、有时啰嗦（这就是 ranges 出现的原因，C++20）。

## 2 · 知识点地图（离散点）

| 族 | 容器 | 布局一句话 | 擅长的 / 不擅长的 |
| --- | --- | --- | --- |
| 序列 | `std::array` | 固定大小内嵌 | 编译期定长、零动态分配；不能变长 |
| | `std::vector` | 连续动态数组 | 尾插/随机访问 O(1)；头部/中间插入 O(n) |
| | `std::deque` | 分块连续 | 头尾 O(1)；随机访问 O(1)（两次间接）；中间 O(n) |
| | `std::list` | 双向链表 | 任意位置插入 O(1)（前提：已有迭代器）；随机访问/缓存差 |
| | `std::forward_list` | 单向链表 | 最小开销；只支持前向 |
| | `std::string` | 连续（实质 vector<char>） | 文本；SSO（小字符串优化）；COW 是历史 |
| 关联 | `set/multiset` | 红黑树 | 有序遍历/范围查询 O(log n)；无重复（*multi* 允许） |
| | `map/multimap` | 红黑树(键) | 按键查找；`operator[]` 会**插入空值**（慎用） |
| 无序 | `unordered_*` | 哈希桶 | 平均 O(1) 查找；无序遍历；重哈希会失效 |
| 适配器 | `stack/queue/prio_queue` | 包装其它容器 | 只用接口 |
| 非拥有 | `std::span` / `string_view` | 指针+长度 | **不拥有**，只读借用（T3）；不能超过被借对象生命周期 |

**迭代器分类**（对应算法要求）：输入 → 前向 → 双向 → 随机访问（`std::sort` 要随机访问；`list` 只能 `list::sort`）。

**key 旁路**：`map::at`（抛 out_of_range）/ `find` / `contains`（C++20）——避免 operator[] 误插入。

## 3 · 决策流程：选容器六问

```text
Q1 元素数量变化小、编译期已知？            → std::array
Q2 主要操作是尾插 + 随机访问？             → std::vector（默认答案！）
Q3 需要头尾都快速进出？                    → std::deque
Q4 需要任意位置插入删除，且插入时已有迭代器？ → std::list / forward_list
Q5 需要按键查找？                        → 有序：map/set  无序：unordered_map/set
Q6 只是只读传递一段数据？                 → std::span / string_view（不拥有！）
补充：矩阵/网格/场（CAE 通用）= 一个 std::vector 平铺 + 自己的索引函数，别叠容器
```

```text
核心提醒：
· 默认 vector；证据不足就不要换别的。
· 「频繁中间插入」先问自己：插入点是怎么来的？如果是遍历找的，list 并不比 vector 快（遍历+插入都是 O(n)，list 缓存还更差）。
· 性能结论一律用 05 §10 实测，别信"别人说 list 快"。
```

## 4 · 常见坑（AI 代码高频）

| 坑 | 症状/原因 | 修法 |
| --- | --- | --- |
| `for(auto x : v)` | 遍历时**拷贝每个元素** | `for(const auto& x : v)` |
| 遍历中 `erase` | vector 迭代器失效（实测：扩容后引用全废） | `it = v.erase(it);`（erase 返回下一个） |
| reserve 后拿引用再插 | 扩容把引用作废 | 先 `reserve()` 定容量，再取引用 |
| `v.size()` 是 `size_t` | `for(int i=0;i<v.size();…)` 有符号/无符号比较警告 | `auto n=v.size();` 或 `size_t` |
| `map[k]` 做查找 | **插入空元素**（找不到也会多一个） | `find` / `contains` / `at` |
| 返回局部 vector 时 `std::move(v)` | **阻止 NRVO**，反而慢 | 直接 `return v;` |
| `vector<bool>` | 是位压缩的位集，不是 bool 数组（`&v[0]` 崩溃） | `deque<bool>` 或其它位集 |
| emplace vs push_back | push_back 会先造临时量 | 需要转发参数时用 `emplace_back` |
| 谓词不满足严格弱序 | `sort` 行为未定义/崩溃 | `x<y` 等价类要对（`!(x<y)&&!(y<x)` 可交换） |
| `erase-remove` 忘了 | 正确删法：`v.erase(std::remove(...), v.end())` | remove 把"幸存者"前移，erase 删尾 |
| 拷入拷出大容器 | 传值 → 深拷贝 | 传 `const&`；需要传出所有权时 `move` 返回 |

```bash
# ① 复现 vector 扩容：noexcept move vs copy（08 已录）
g++ -std=c++17 /tmp/v2/vec.cpp -o vec && ./vec
#    → C(noexcept move): copy=0 move=15    D(copy-only): copy=15

# ② 看扩容序列（容量 1,2,4,8…）——同一个程序已经打印

# ③ 迭代器失效演示：reserve 后拿引用再 push_back，ASan 抓
g++ -std=c++17 -g -O1 -fsanitize=address -x c++ - <<'EOF'
#include <vector>
int main(int argc, char**){
    std::vector<int> v{1,2,3};
    v.reserve(4);
    int& r = v[1];          // 引用 v[1]
    v.push_back(4); v.push_back(5); v.push_back(6);   // 扩容
    return r == 2 ? 0 : 1;  // 引用已悬垂（此处读是 UB，ASan 能抓）
}
EOF

# ④ 复杂度自查：对 list 做 v[i] 会怎样（编译错误吗？不，是慢）+ 确认 sort 需要随机访问迭代器
```

## 7 · 自测三问

- **判定**：`std::list<int>` 能用 `std::sort` 吗？为什么？（不能——迭代器不是随机访问；用 `list::sort`）
