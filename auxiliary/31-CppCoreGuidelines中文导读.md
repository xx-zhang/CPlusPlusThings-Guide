## 2 · P: Philosophy —— 13 条**完整中译**

> 这一节是"为什么要这些规则"，其余 447 条都是它的落地。

| # | 中文 | 要点 | 挂靠 |
| --- | --- | --- | --- |
| **P.1** | **在代码里直接表达想法** | 别靠注释/命名绕；能写成类型/函数的就别靠心智 | 元2 · T9 |
| **P.2** | **用 ISO 标准 C++ 写** | 别依赖方言扩展；可移植性是底线 | T11 |
| **P.3** | **表达意图** | 名字/类型/接口说明"做什么"，而非"怎么做" | 元2 · T9 |
| **P.4** | 理想上**静态类型安全** | 类型系统的漏洞（union/强转/数组）是 bug 之源 | T8 · A2 |
| **P.5** | **优先编译期检查**而非运行期检查 | 编译期发现 = 零运行期成本 + 零上线风险 | **元3** |
| **P.6** | **编译期查不了的，要能在运行期查** | 断言/契约/边界检查 | T9 · `05` |
| **P.7** | **尽早捕获运行期错误** | 越早越便宜、越易定位 | `14` · `03` |
| **P.8** | **不要泄漏任何资源** | 内存/句柄/锁/文件一视同仁 | **A5** · `16` |
| **P.9** | **不要浪费时间与空间** | 性能是需求的一部分（不是唯一） | 元1 · `13` |
| **P.10** | **优先不可变数据** | 不可变 = 少一类 bug（并发下尤其） | T1 · `Con` · `11` |
| **P.11** | **把混乱封装起来，别让它散布** | 复杂性关进小盒子 | A5 · `19` · `27` |
| **P.12** | **适当使用辅助工具** | 告警/静态分析/sanitizer/fuzzer | **`05` · `24` 五层关卡** |
| **P.13** | **适当使用支持库** | 别重造轮子 | `23` |

**P.4→P.5→P.6 是一个递进**：静态类型安全 ⟶ 编译期检查 ⟶ 编译期查不了的运行期检查。这与我们 **A2 + A4 + 元3** 是同一套思想。

### In · 前言（1 条）

- **In.0** 🏛 别慌！——规则是渐进采用的，不必一次全上。

### I · 接口（20 条）

- **I.1** 🏛 让接口显式（不用全局状态传隐含参数）
- **I.2** 🏛 避免非 `const` 全局变量
- **I.3** 🏛 避免单例
- **I.4** 🏛 接口要精确且强类型（别用裸 `int` 当尺寸、别用 `bool` 传多义参数）
- **I.5** 📖 声明前置条件
- **I.6** 📖 用 `Expects()` 表达前置条件
- **I.7** 📖 声明后置条件
- **I.8** 📖 用 `Ensures()` 表达后置条件
- **I.9** 📖 模板接口用 concepts 文档化参数要求
- **I.10** 🏛 用异常表示"无法完成要求的任务"
- **I.11** 🏛 **绝不用裸指针/裸引用转移所有权**
- **I.12** 📖 "不能为空"的指针用 `not_null`
- **I.13** 🏛 不要把数组当单个指针传（用 `span`）
- **I.22** 🏛 避免全局对象的复杂初始化（→ 我们 T12 静态初始化灾难）
- **I.23** 🏛 函数参数个数要少
- **I.24** 📖 避免"两个相邻参数可交换且含义不同"（调用方易写反）
- **I.25** 📖 优先用空抽象类做接口，而非类层次
- **I.26** 🏛 要跨编译器 ABI 就用 C 风格子集（→ T11）
- **I.27** 🏛 要稳定库 ABI 考虑 Pimpl（→ `19` · `22 §4`）
- **I.30** 📖 把规则违反封装起来（集中处理例外）

### F · 函数（36 条）

#### F.def · 函数定义

- **F.1** 🏛 把有意义的操作打包成命名良好的函数
- **F.2** 📖 一个函数只做一件逻辑事
- **F.3** 📖 函数保持短小简单
- **F.4** 🏛 可能需编译期求值 → `constexpr`（元3）
- **F.5** 📖 很小且时间关键的函数可 `inline`（但 `inline` 本职是 ODR，见 T6）
- **F.6** 🏛 函数**必须不抛**才标 `noexcept`（→ T9；CG 亦警告勿滥用）
- **F.7** 🏛 通用接口用 `T*`/`T&`，别用智能指针当参数（→ `16`）
- **F.8** 📖 优先纯函数（无副作用、结果只依赖参数）
- **F.9** 📖 未使用的参数不要命名
- **F.10** 📖 可复用的操作给它起名字
- **F.11** 📖 只在一处用的简单函数对象 → 无名 lambda

#### F.call · 参数传递（⭐ 全篇最实用）

- **F.15** 🏛 优先用**简单、常规**的传参方式（别炫技）
- **F.16** 🏛 **"输入"参数**：廉价的按值传，其余按 `const&`
- **F.17** 🏛 **"输入-输出"参数**：按非 `const` 引用传
- **F.18** 🏛 **"将被移动"参数**：按 `X&&` 传并在函数内 `std::move`
- **F.19** 🏛 **"转发"参数**：按 `TP&&` 传且只 `std::forward`（→ T7）
- **F.20** 🏛 **"输出"优先返回值**，而非出参
- **F.21** 🏛 要返回多个值 → 返回 `struct`
- **F.22** 📖 用 `T*`/`owner<T*>` 表示单个对象
- **F.23** 📖 用 `not_null<T>` 表示"空不是合法值"
- **F.24** 📖 用 `span<T>` 表示半开区间
- **F.25** 📖 用 `zstring`/`not_null<zstring>` 表示 C 串
- **F.42** 📖 返回 `T*` 只表示"位置"
- **F.43** 🏛 **绝不返回指向局部对象的指针/引用**（→ T3 悬垂）
- **F.44** 📖 拷贝不划算且"无对象"不合法时返回 `T&`
- **F.45** 🏛 **不要返回 `T&&`**
- **F.46** 📖 `main()` 返回 `int`
- **F.47** 🏛 赋值运算符返回 `T&`
- **F.48** 🏛 **不要 `return std::move(local)`**（阻止拷贝消除 → `13 §1.4`）
- **F.49** 🏛 不要返回 `const T`（会阻止移动）
- **F.50** 📖 函数做不到的（要捕获局部）→ 用 lambda
- **F.51** 📖 二选一时优先默认参数，而非重载
- **F.52** 🏛 局部（含传给算法）的 lambda：按引用捕获
- **F.53** 🏛 **非局部**使用（返回/存堆/传其它线程）的 lambda：别按引用捕获
- **F.54** 🏛 捕获 `this` 或成员时，**别用 `[=]` 默认捕获**
- **F.60** 📖 `T&` 无法表示"无参数"时改用 `T*`

### C · 类与类层次（97 条）⭐ 最大一节

#### C 基础

- **C.1** 🏛 相关数据组织成 `struct`/`class`
- **C.2** 🏛 **有不变式用 `class`；成员可独立变化用 `struct`**（实用判据）
- **C.3** 📖 用类区分"接口"与"实现"
- **C.4** 🏛 只有需要直接访问表示时才做成成员函数
- **C.5** 📖 辅助函数放在目标类所在命名空间
- **C.7** 📖 别在同一语句里"定义类/枚举 + 声明该类型变量"
- **C.8** 📖 有非 public 成员就用 `class`
- **C.9** 🏛 尽量少暴露成员

#### C.concrete · 具体类型

- **C.10** 🏛 优先具体类型，而非类层次
- **C.11** 🏛 让具体类型"规则化"（可拷贝/可比较/可哈希…）
- **C.12** 🏛 可拷贝/可移动类型里**别放 `const` 成员或引用成员**（→ T3/T4）
- **C.13** 📖 若成员 B 依赖成员 A，先声明 A（→ 初始化顺序，T12）

#### C.defop · 默认操作（→ 我们的 T4）

- **C.20** 🏛 **能不定就不定**（rule of zero）
- **C.21** 🏛 **定了/`=delete` 任一拷贝、移动、析构 → 全都定或全都 delete**（rule of 5）
- **C.22** 🏛 让默认操作彼此**一致**

#### C.dtor · 析构（→ T2/T5）

- **C.30** 🏛 析构时需显式动作 → 定义析构
- **C.31** 🏛 类获取的所有资源**必须**由析构释放（RAII）
- **C.32** 🏛 有裸指针/引用成员 → 想清楚**是否拥有**
- **C.33** 🏛 有拥有型指针成员 → 定义析构
- **C.35** 🏛 **基类析构：要么 public+virtual，要么 protected+非 virtual**（与 T5 **完全一致**）
- **C.36** 🏛 **析构不得失败**
- **C.37** 🏛 析构标 `noexcept`

#### C.ctor · 构造

- **C.40** 🏛 有不变式 → 定义构造函数
- **C.41** 🏛 构造函数应产出**完全初始化**的对象
- **C.42** 🏛 构造不出合法对象 → 抛异常
- **C.43** 📖 可拷贝的类应有默认构造
- **C.44** 📖 默认构造应简单且不抛
- **C.45** 🏛 别写"只初始化成员"的默认构造 → 用**默认成员初始化器**（NSDMI）
- **C.46** 🏛 **单参构造默认声明为 `explicit`**（元2）
- **C.47** 🏛 按**成员声明顺序**初始化
- **C.48** 🏛 常量初始化优先用 NSDMI，而非构造初始化列表
- **C.49** 🏛 构造函数里优先**初始化**而非赋值
- **C.50** 📖 初始化期间需"虚行为" → 用工厂函数（→ T5：构造期不派发）
- **C.51** 📖 用**委托构造**表达公共动作
- **C.52** 📖 用**继承构造**（`using Base::Base`）导入

#### C.copy · 拷贝与移动（→ T4）

- **C.60** 🏛 拷贝赋值：非 virtual、参数 `const&`、返回非 `const&`
- **C.61** 🏛 拷贝操作就该**拷贝**
- **C.62** 🏛 拷贝赋值要**自赋值安全**
- **C.63** 🏛 移动赋值：非 virtual、参数 `&&`、返回非 `const&`
- **C.64** 🏛 移动操作要真移动，且**源对象留在合法状态**（→ T4）
- **C.65** 🏛 移动赋值要自赋值安全
- **C.66** 🏛 **移动操作必须 `noexcept`**（否则容器退化为拷贝 → 我们实测过）
- **C.67** 🏛 多态类**应抑制 public 拷贝/移动**（切片！）
- **C.80** 🏛 想显式用默认语义 → `=default`
- **C.81** 🏛 想禁用默认行为且无替代 → `=delete`
- **C.82** 🏛 **别在构造/析构里调虚函数**（与 T5 的实用推论**完全一致**）
- **C.83** 🏛 值语义类型考虑提供 `noexcept` 的 `swap`
- **C.84** 🏛 `swap` 不得失败
- **C.85** 🏛 `swap` 标 `noexcept`
- **C.86** 🏛 让 `==` 对操作数类型**对称**且 `noexcept`
- **C.87** 🏛 小心基类上的 `==`（切片比较）
- **C.89** 🏛 `hash` 标 `noexcept`
- **C.90** 🏛 **依赖构造/赋值，别用 `memset`/`memcpy`**（→ `28 §3.4` 填充位）

#### C.con · 容器与资源句柄

- **C.100** 📖 自造容器要**遵循 STL 约定**
- **C.101** 📖 容器给**值语义**
- **C.102** 📖 容器给**移动操作**
- **C.103** 📖 容器给**初始化列表构造**
- **C.104** 📖 容器给"置空"的默认构造
- **C.109** 📖 指针语义的资源句柄提供 `*` 和 `->`

#### C.hier · 类层次（→ T5）

- **C.120** 🏛 只有**本质层次结构**才用类层次
- **C.121** 🏛 基类当接口用 → 做成**纯抽象类**
- **C.122** 🏛 需彻底分离接口/实现 → 抽象类
- **C.126** 📖 抽象类通常不需要用户写的构造函数
- **C.127** 🏛 **有虚函数的类应有虚析构或 protected 析构**
- **C.128** 🏛 **虚函数在 `virtual`/`override`/`final` 中恰好写一个**（→ T5）
- **C.129** 🏛 区分**实现继承**与**接口继承**
- **C.130** 🏛 多态类深拷贝 → 优先**虚 `clone`**，而非 public 拷贝构造/赋值
- **C.131** 📖 避免琐碎的 getter/setter
- **C.132** 🏛 **别无缘无故把函数做成 `virtual`**（避免白付间接跳转）
- **C.133** 🏛 避免 `protected` 数据
- **C.134** 🏛 所有非 `const` 成员**同一访问级别**
- **C.135** 📖 多继承用于表达**多个不同接口**
- **C.136** 📖 多继承用于表达**实现属性并集**
- **C.137** 📖 用虚基类避免过于泛化的基类（→ A3 虚继承布局）
- **C.138** 🏛 **用 `using` 为派生类与其基类建立重载集**（→ `22 §1.2` 名字隐藏！）
- **C.139** 🏛 **谨慎使用 `final`** —— ⚠️ 与我们的张力（我们强调 `final` 助去虚化；两边都对：`final` 是承诺，承诺要真成立）
- **C.140** 🏛 别给虚函数与其覆写者**不同的默认参数**（→ T5：默认参数静态绑定）
- **C.145** 📖 通过指针/引用访问多态对象
- **C.147** 📖 找不到类算错误 → `dynamic_cast` 到**引用**（抛 `bad_cast`）
- **C.148** 📖 找不到类也算合法 → `dynamic_cast` 到**指针**（返回 `nullptr`）
- **C.149** 🏛 `new` 出来的对象用 `unique_ptr`/`shared_ptr` 管（→ `16`）
- **C.152** 🏛 **绝不把"派生类数组指针"赋给"基类指针"**
- **C.153** 🏛 **优先虚函数而非强制转换**

#### C.over · 重载与运算符

- **C.160** 📖 运算符只用于符合**常规语义**的操作
- **C.161** 📖 对称运算符用**非成员函数**
- **C.162** 📖 重载"大约等价"的操作
- **C.163** 📖 只对"大约等价"的操作重载
- **C.164** 🏛 **避免隐式转换运算符**（元2）
- **C.165** 📖 用 `using` 做定制点
- **C.166** 📖 只在整个智能指针/引用体系里才重载一元 `&`
- **C.167** 📖 运算符用于其常规含义
- **C.168** 🏛 重载运算符定义在**操作数所在命名空间**（→ ADL，`22 §1.1`）
- **C.170** 📖 想重载 lambda → 用泛型 lambda

#### C.union · 联合体（→ A3 · `28`）

- **C.180** 🏛 `union` 用于省内存
- **C.181** 🏛 避免"裸 union"（用 variant）

- **SL.con.2** 🏛 **默认用 `vector`**，除非有理由换（→ `10 §3` 选容器六问）
- **SL.con.3** 🏛 避免越界错误
- **SL.con.4** 🏛 非 trivially-copyable 类型别用 `memset`/`memcpy`

#### SL.str · 字符串（→ `23 §2`）

- **SL.str.1** 🏛 用 `std::string` 拥有字符序列
- **SL.str.2** 🏛 引用字符序列用 `string_view`/`span<char>`
- **SL.str.3** 📖 C 风格零终止串用 `zstring`/`czstring`
- **SL.str.4** 📖 单个字符用 `char*`
- **SL.str.5** 📖 不一定是字符的字节值用 `std::byte`
- **SL.str.10** 📖 需要 locale 敏感操作时用 `std::string`
- **SL.str.11** 📖 需要改动字符串时用 `span<char>` 而非 `string_view`
- **SL.str.12** 📖 想要标准库 `string` 的字面量用 `s` 后缀

#### SL.io · 输入输出（→ `23 §9`）

- **SL.io.1** 📖 必须时才用字符级输入
- **SL.io.2** 🏛 读输入时**始终考虑畸形输入**
- **SL.io.3** 📖 优先 `iostream`
- **SL.io.10** 📖 不用 printf 家族时调 `sync_with_stdio(false)`
- **SL.io.50** 🏛 **避免 `endl`**（强制 flush → 慢）

#### SL.C

- **SL.C.1** 🏛 **别用 `setjmp`/`longjmp`**

### A · 架构（3 条）

- **A.1** 📖 稳定代码与不稳定代码分开
- **A.2** 📖 可能复用的部分做成库
- **A.4** 🏛 **库之间不应有循环依赖**

### NR · 非规则与迷思（7 条）⭐ 破教条

- **NR.1** 🏛 **别坚持"所有声明都在函数顶部"**
- **NR.2** 🏛 **别坚持"函数只能有一个 `return`"**
- **NR.3** 🏛 **别回避异常**（⚠️ 与 ROS2/嵌入式 `-fno-exceptions` 有张力 → 见 `E.25-E.27`）

- **NR.6** 🏛 别把所有清理放函数末尾再 `goto exit`
- **NR.7** 🏛 别把数据成员做成 `protected`

## 4 · 对账：CG 与我们体系

### 4.1 高度一致（**互证**）——不同作者、不同方法，同一结论

| 结论 | CG | 我们 |
| --- | --- | --- |
| 头文件不得放（非 inline）函数/对象定义 | **SF.2** | **A1 · T6 · lessons/01** |
| 基类析构：public+virtual 或 protected+非 virtual | **C.35** | **T5**（实测过虚析构删移动的代价） |
| 别在构造/析构里调虚函数 | **C.82** | **T5 实用推论** |
| 移动操作必须 `noexcept` | **C.66** | **T9**（实测：否则容器退化拷贝） |
| 不要 `return std::move(local)` | **F.48** | **`13 §1.4`** |
| 别依赖函数实参求值顺序 | **ES.44** | **T10**（实测：同机不同上下文结果相反） |
| 别用 `volatile` 做同步 | **CP.8 · CP.200** | **`06 §1.5` + `11`**（实测丢计数） |
| 别自己写双重检查锁 | **CP.110** | **T2**（函数内 static 已线程安全，实测） |
| 用 `{}` 初始化（拦窄化） | **ES.23** | **T8 · `22 §3`**（实测） |
| 用 `nullptr` 而非 `0` | **ES.47** | **`22 §2.3`**（实测：`f(0)` 歧义） |
| 没有测量不下性能结论 | **Per.6** | **`13 §3` 铁律** |
| 计算移到编译期 | **Per.11 · P.5** | **元3** |
| 用 RAII，避免裸 new/delete | **R.1 · R.11 · E.6** | **A5 · `16`** |
| 优先 `unique_ptr` 而非 `shared_ptr` | **R.21** | **T4 所有权三态 · `16`** |
| 别用 union 做类型双关 | **C.183** | **A2 · `22 §4`** |
| 默认 `const`/`constexpr` | **Con.1-5** | **T1 · 元2 · 元3** |
| 优先虚函数而非强转 | **C.153** | **T5** |
| 用 `using` 恢复被隐藏的重载集 | **C.138** | **`22 §1.2`**（我们实测：静默选错） |

> **18 条独立互证**——两套体系互不知情却得出同一结论，这是「结论可信」的强证据（我们 0.5.2 的「多路径互证」在体系间也成立）。

### 4.2 存在张力（**两边都对，看前提**）

| 主题 | CG 立场 | 我们立场 | 化解 |
| --- | --- | --- | --- |
| `final` | **C.139 谨慎使用** | **T5**：`final` 是去虚化的钥匙，值得主动用 | 都对：`final` 是**承诺**（"不再被继承"）。承诺真成立时用它换性能；不确定就别承诺 |
| 异常 | **NR.3 别回避异常**；E.2 用异常报错 | `09`：预期错误用错误码/`expected`；具身智能常有 `-fno-exceptions` | CG 自己也给了出口：**E.25-E.27**（不能抛时模拟 RAII/快速失败/系统化错误码） |
| `unsigned` | **ES.101/102/106/107**：算术用有符号、位操作用无符号、别拿它做下标 | `10 §4` 只说"`size_t` 下标会有告警" | CG 更系统；**采纳它的判据**（这是我们的缺口） |
| 单参构造 `explicit` | **C.46** 默认 explicit | 元2 同向，但没给"默认"这么强的措辞 | 采纳 CG 的默认立场 |

### 4.3 CG 有、我们**没有**的（真缺口，按价值排序）

| CG | 内容 | 我们的状态 |
| --- | --- | --- |
| **GSL** | `span`/`not_null`/`owner`/`Expects`/`Ensures`/`narrow_cast`/`finally` | T9 有**契约理论**，但没有这套**具体类型**——**值得补** |
| **Pro（Profiles）** | 类型安全 / 边界安全 / 生命周期安全 三个**可强制子集** | 完全没有；这是"按 profile 裁剪语言"的机制 |
| **ES.100-107 算术** | 有符号/无符号的系统判据 | 只有零散提及（真缺口） |
| **CP.44** | 记得给 `lock_guard` 命名（无名临时量=立即解锁） | 无——**很好的一条**，已补进 `11` 的建议 |
| **I.6/I.8** | `Expects`/`Ensures` 前置后置条件的**表达方式** | T9 有理论，无工具 |
| **E.19 `final_action`** | scope guard 惯用法 | 只有"RAII 泛化"的概念 |
| **NL（20 条）** | 命名与布局 | 完全没有（约定域，但工程上必需） |
| **T.60/T.61/T.62** | 模板上下文依赖、SCARY、非依赖成员 | `12` 有模板，无这些编译时间优化 |
| **I.24** | 相邻参数可对调的坑 | 无 |
| **Appendix B** | 旧代码现代化路线 | 无 |

### 4.4 我们有、CG **弱或没有**的（我们的不可替代位置）

| 我们有 | CG 对应 | 差别 |
| --- | --- | --- |
| **A2 抽象机/UB 的机制解释** | 只有规则（ES.103 等） | CG 说"不改怎么做"，不说"为什么这是 UB" |
| **三源对齐 + 可证伪方法论**（00） | `In.force` 有 Enforcement 哲学 | CG 要求可强制，但**未实现为脚本**；我们 `check.sh` 13 项可执行 |
| **实测证据库**（`06`/`08`/`29`） | 官方自认示例未验证 | 我们每条结论附命令+输出 |
| **T7/T8 值类别与类型代数** | 分散在 F.18/F.19/ES.56 | 我们有统一的「引用折叠/推导」代数 |
| **A1/T6/`19`/`22 §4` 的链接与 ABI 体系** | 只有 SF 节 + I.26/I.27 | 我们把 ODR/符号/ABI 做成了一条线 |

**一句话结论**：**CG 是「该怎么做」的权威字典，我们是「为什么 + 怎么验 + 怎么学」的体系。两者叠用，而不是二选一。**
