> 每次实测都打开这个文件。**所有命令都在本机验证过**（环境见文末）。
>
> 核心用法：**先查下面的「索引表」，找到你要验的东西，抄命令。**

## 0 · 索引表：我要验 X，用哪个命令

| 我想验证 | 用哪一节 | 关键命令 |
| --- | --- | --- |
| 这段代码能不能编译 | §1 | `g++ -fsyntax-only` |
| 预处理器展开成了什么 | §2 | `g++ -E` |
| **符号是强还是弱？内部还是外部链接？** | §3 | `nm -C` |
| 类多大？成员在哪？ | §4 | `sizeof` + `offsetof` |
| **类的完整内存布局（含 vptr / 虚基类）** | §4 | `-fdump-lang-class=-` |
| 编译器实际生成了什么代码 | §5 | `-S -O2` |
| **虚函数被去虚化了吗？** | §6 | `-S -O2` 找 `jmp *(%rax)` |
| **有没有 UB？** | §7 | `-fsanitize=address,undefined` |
| **有没有 ODR 违规（跨 TU 类型不一致）？** | §8 | `-flto -Wodr` |
| 有没有数据竞争？ | §9 | `-fsanitize=thread` |
| 这段代码快不快，瓶颈在哪 | §10 | `perf stat` / `perf record` |
| gcc 说得对不对（换编译器交叉验证） | §11 | `clang++` |
| **每次实测都要做的标准动作** | §12 | 一键脚本 |

## §1 · 编译与语法检查

```bash
# 只要语法，不链接（最快，适合扫仓库）
g++ -std=c++17 -fsyntax-only -w file.cpp

# 严肃模式：打开高价值警告
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion \
    -fsyntax-only file.cpp

# 把警告当错误（CI 用；排查别人的代码时很有用）
g++ -std=c++17 -Wall -Wextra -Werror file.cpp -o prog

# 完整编译 + 保留调试信息
g++ -std=c++17 -g -O0 file.cpp -o prog

# 多文件
g++ -std=c++17 -Wall -Wextra a.cpp b.cpp main.cpp -o prog
```

### 标准版本对照（验证「这个特性在 C++11 能用吗」）

```bash
for std in c++98 c++11 c++14 c++17 c++20 c++23; do
  printf "%-6s " "$std"
  g++ -std=$std -fsyntax-only file.cpp 2>/dev/null && echo "✓ 通过" || echo "✗ 失败"
done
```

**技巧**：想知道某个特性是不是 C++17 才有的，就固定用 `-std=c++14` 编一遍。本目录的实测就是这么做的：

```text
$ g++ -std=c++14 st2.cpp      # static inline int cnt = 0;
warning: inline variables are only available with '-std=c++17'   ← 确认是 C++17 特性
```

## §2 · 看预处理器做了什么

```bash
# 展开所有宏和 #include
g++ -std=c++17 -E file.cpp

# 只看宏展开，去掉 #include 的噪音（技巧：把 #include 去掉再跑）
g++ -std=c++17 -E -P file.cpp | tail -20

# 保留注释（看宏到底长什么样）
g++ -std=c++17 -E -C file.cpp
```

**用途**：验证宏的展开规则。本目录的实测例子：

```bash
# 验证 # 不做宏展开、## 结果会被重新扫描
# STR(NAME) → "NAME"    XSTR(NAME) → "hello"    CAT(hello,_tok) → "from hello_tok"
```

## §3 · 看符号（⭐ 最常用）

```bash
g++ -std=c++17 -c file.cpp -o file.o

nm file.o               # 原始（名字被 mangle 了）
nm -C file.o            # demangle，可读
nm -C -a file.o         # 全部符号，含调试用
nm -C --defined-only file.o   # 只看本文件定义的
nm -C -u file.o         # 只看未定义引用（U）—— 找 undefined reference 的线索
```

### 符号字母速查（详见 `02-正交轴与术语速查.md`）

```text
T  全局代码（外部链接）   ← 多个 TU 都有就 multiple definition
t  局部代码（内部链接）   ← static 函数
W  弱符号                ← inline / 模板 / constexpr / 类内定义的成员函数
R  全局只读数据           ← C 的 const int c
r  局部只读数据           ← C++ 的 const int c（内部链接！）
D/d  已初始化数据（B/b 未初始化）
U  未定义引用             ← 需要链接器去找
V  弱对象                ← C++17 inline 变量
```

### 为什么这是判断链接性的最快方法

```bash
# C 与 C++ 的 const 链接性差异 —— 一条命令看出来
echo 'const int c = 42;' > x.c
gcc  -c x.c -o x_c.o   && echo "C  : $(nm x_c.o | grep ' c$')"     # R c  ← 外部
g++  -c x.c -o x_pp.o -x c++ && echo "C++: $(nm x_pp.o | grep ' c$')"  # r c  ← 内部
```

### 看 mangled 名字（理解 `extern "C"` 的关键）

```bash
nm file.o | grep add          # 看到 _Z3addii 之类
c++filt _Z3addii              # → add(int, int)
```

## §4 · 看类布局

```bash
# ① 快速看大小
cat > sz.cpp <<'EOF'
#include <cstdio>
#include <cstddef>
struct A { char a; int b; };
struct B : A { short c; long d; };
int main(){
  std::printf("sizeof(A)=%zu sizeof(B)=%zu\n", sizeof(A), sizeof(B));
}
EOF
g++ -std=c++17 sz.cpp -o sz && ./sz

# ② 看成员偏移
#    ⚠️ offsetof 对非 standard-layout 类型是"条件支持"，GCC 允许，但会告警
g++ -std=c++17 -w -DUSE_OFFSETOF ...   # 或在代码里直接用 offsetof(B, d)
```

### ⭐ 完整内存布局（含 vptr、虚基类偏移）—— 这个命令能省掉大量猜测

```bash
g++ -std=c++17 -c file.cpp -o /dev/null -fdump-lang-class=-
```

输出示例（本目录实测）：

```text
Vtable for MA
MA::_ZTV2MA: 6 entries
0     (int (*)(...))0
8     (int (*)(...))(& _ZTI2MA)
16    (int (*)(...))VA::fun          ← 第一张子虚表
24    (int (*)(...))-8
32    (int (*)(...))(& _ZTI2MA)
40    (int (*)(...))VB::fun2         ← 第二张子虚表

Class MA
   size=16 align=8                    ← 16 字节 = 2 个 vptr
   base size=16 base align=8
```

**看什么**：

- `size=` → 总大小
- vtable 里有几段（`-8`、`-16` 这种负偏移）→ 有几个多态基类子对象
- 虚基类的偏移存在哪（有 vptr 时通常存在虚表里，没有额外指针）

### clang 的等价命令（交叉验证布局）

```bash
clang++ -std=c++17 -Xclang -fdump-record-layouts -c file.cpp -o /dev/null
```

## §5 · 看汇编

```bash
# 生成汇编（-o - 输出到 stdout）
g++ -std=c++17 -O2 -S file.cpp -o -

# 带源码行号注释，方便对应回 C++ 行
g++ -std=c++17 -O2 -S -fverbose-asm file.cpp -o -

# 只提取某一个函数
g++ -std=c++17 -O2 -S file.cpp -o - | sed -n '/^_Z1fv:/,/^\t.size/p'

# 用 c++filt 解 mangle
g++ -std=c++17 -O2 -S file.cpp -o - | c++filt | less
```

### ⚠️ 铁律

> **`-O0` 的汇编不能作为性能或「编译器做了什么」的证据。**
> 仓库 `pointer_refer/README.md` 就是拿 `-O0` 汇编得出「引用和指针完全一样、没有性能差距」——实验设计错了。

**正确的对比方法**：`-O2` 看实际优化结果，`-O0` 只看「语义上编译器理解成了什么」。

### 常用读法

```text
movl   $42, %eax         立即数 42（= 编译期算完了 / 常量折叠）
movl   $42, -8(%rbp)     写栈
movq   (%rdi), %rax      从 rdi 指向的内存读 8 字节 → 取 vptr
jmp    *(%rax)           间接跳转 → 动态派发（没去虚化）
cmpq / jne .L8           比较后条件跳转 → 推测去虚化
```

## §6 · 看去虚化（virtual 到底有没有成本）

```bash
cat > virt.cpp <<'EOF'
struct Base { virtual int f() const { return 1; } virtual ~Base() = default; };
struct Derived : Base { int f() const override { return 2; } };
struct Sealed final : Base { int f() const override { return 3; } };
int call_ref(Base& b)       { return b.f(); }
int call_local()            { Derived d; Base& b = d; return b.f(); }
int call_final(Sealed& s)   { return s.f(); }
int call_direct(Derived& d) { return d.f(); }
EOF
g++ -std=c++17 -O2 -S virt.cpp -o - | c++filt | sed -n '/call_ref/,/ret/p'
```

本目录实测结果：

```text
call_ref(Base&):                                 ← 真动态派发
    movq (%rdi), %rax
    jmp  *(%rax)

call_local():        movl $2, %eax ; ret         ← 完全消除
call_final(Sealed&): movl $3, %eax ; ret         ← 完全消除（参数是引用！）
call_direct(Derived&):                           ← 推测去虚化
    cmpq %rdx, %rax
    jne  .L8
    ...
```

**结论**：判据不是「实际对象 vs 引用」，而是「**编译器能否证明动态类型**」。
想帮编译器证明，就加 `final`（见 `01` 的 T5）。

## §7 · 检测 UB（开发期必开）

```bash
# ASan（内存）+ UBSan（未定义行为）—— 最常用组合
g++ -std=c++17 -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer \
    -fno-sanitize-recover=all file.cpp -o prog
./prog

# 只要 ASan（更快）
g++ -std=c++17 -g -O1 -fsanitize=address file.cpp -o prog

# 只要 UBSan
g++ -std=c++17 -g -O1 -fsanitize=undefined file.cpp -o prog
```

### 各 sanitizer 抓什么

| Sanitizer | 抓 | 编译器 |
| --- | --- | --- |
| **ASan** | 越界（栈/堆/全局）、use-after-free、double-free、泄漏（`ASAN_OPTIONS=detect_leaks=1`） | gcc / clang |
| **UBSan** | 有符号溢出、空指针解引用、对齐、部分类型双关、非法移位 | gcc / clang |
| **MSan** | **未初始化读** | **仅 clang**（`-fsanitize=memory`） |
| **TSan** | **数据竞争** | gcc / clang |

本目录实测（一个程序同时有越界、有符号溢出、未初始化读）：

```text
$ ./ub
ub.cpp:5:26: runtime error: index 6 out of bounds for type 'int [3]'
ub.cpp:5:14: runtime error: load of address ... with insufficient space for an object of type 'int'
==66761==ERROR: AddressSanitizer: stack-buffer-overflow ...
SUMMARY: AddressSanitizer: stack-buffer-overflow /tmp/v2/ub.cpp:5 in main

$ ./ub2      （不加 sanitizer）
30574
0
(静默，什么都不报)      ← 这就是"看起来能跑"的 UB
```

> ⚠️ **注意：sanitizer 在第一个错误处就会中止**。上面那个程序的中止点在越界，所以后面的有符号溢出没被报告。**修一个跑一次**，不要指望一次全抓出来。

## §8 · 检测 ODR 违规（⭐ 别人很少做，但很值）

**问题**：两个 TU 里的 `struct S` 定义不同（比如一个改了字段），各自编译**完全不报错**，运行时读到的内存布局对不上。

```bash
g++ -std=c++17 -O2 -flto -Wodr a.cpp b.cpp main.cpp -o prog
```

本目录实测：

```text
$ g++ -std=c++17 -O2 -flto -Wodr odr1.cpp odr2.cpp odrm.cpp -o odrm
odr1.cpp:1:8: warning: type 'struct S' violates the C++ One Definition Rule [-Wodr]
odr2.cpp:1:8: note: a different type is defined in another translation unit
odr1.cpp:1:16: note: the first difference of corresponding definitions is field 'a'

$ g++ -std=c++17 -O2 odr1.cpp odr2.cpp odrm.cpp -o odrm2      # 不加 LTO
（什么都不报，链接通过）
```

> **`-flto -Wodr` 是少数几个能跨 TU 检查 ODR 的手段**。审大项目时把它加进构建，性价比很高。

## §9 · 检测数据竞争

```bash
g++ -std=c++17 -g -O1 -fsanitize=thread -pthread race.cpp -o race
./race

# TSan 抓不到就加大并发压力
for i in $(seq 1 50); do ./race || break; done
```

**注意**：TSan 与 ASan **不能同时开**，要分开跑。

## §10 · 性能分析

```bash
# 事件计数（cache miss / 分支预测失败 / IPC）
perf stat ./prog

# 采样找出热点函数
perf record -g ./prog && perf report

# 堆内存
valgrind --tool=massif ./prog
valgrind --leak-check=full ./prog        # 泄漏详情（比 ASan 详细，但慢 20-50 倍）

# 系统调用
strace -c ./prog

# 静态指令吞吐分析（需要装 llvm 工具：apt install llvm-19-tools）
llvm-mca-19 -mcpu=skylake -iterations=100 snippet.s
```

**本机可用性**（已实测）：

```text
nm ✓  objdump ✓  readelf ✓  c++filt ✓  gdb ✓
perf ✓  valgrind ✓  strace ✓  clang++ ✓  g++ ✓
llvm-mca-19 ✗  llvm-objdump-19 ✗  llvm-mc-19 ✗   ← 需 apt install llvm-19-tools
```

## §11 · 交叉验证（换编译器）

**规则**：涉及**布局、ABI、优化行为**的结论，**至少用两个编译器验证**。语言规则则不必。

```bash
clang++ -std=c++17 -O2 -S file.cpp -o -        # 看 clang 的汇编
clang++ -std=c++17 -Xclang -fdump-record-layouts -c file.cpp -o /dev/null

# 把 gcc 的警告和 clang 的警告都看一遍（两边抓的 bug 不同）
g++     -std=c++17 -Wall -Wextra -fsyntax-only file.cpp
clang++ -std=c++17 -Wall -Wextra -fsyntax-only file.cpp
```

**实测差异提示**：`this/README.md` 那段 `Person(char*)` 用字符串字面量调用，
g++ 报 `warning: ISO C++ forbids converting a string constant to 'char*'`，
clang++ 报 `warning: ISO C++11 does not allow conversion from string literal to 'char *'`。
**两个都只告警不报错**（为了兼容老代码），但**都是不合法代码**。

## §12 · 一键验证脚本（推荐存成 `verify.sh`）

这是 `03-学习方法与步骤.md` 六步法里「③ 实测」的标准动作。**每个主题都跑一遍**：

```bash
#!/usr/bin/env bash
# 用法: ./verify.sh file.cpp [额外源文件...]
set -u
SRC=${1:?用法: verify.sh file.cpp}; shift || true

echo "=== 1. 严格语法检查 (C++20) ==="
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -Wconversion \
    -fsyntax-only "$SRC" "$@" 2>&1 | head -40

echo; echo "=== 2. 各标准版本是否通过 ==="
for std in c++11 c++14 c++17 c++20; do
  printf "  %-6s " "$std"
  g++ -std=$std -fsyntax-only -w "$SRC" "$@" 2>/dev/null && echo "✓" || echo "✗"
done

echo; echo "=== 3. 编译产物与符号 ==="
mkdir -p .verify && cd .verify
g++ -std=c++17 -c "../$SRC" -o out.o 2>/dev/null && nm -C out.o | head -30

echo; echo "=== 4. 类布局（如果有类）==="
g++ -std=c++17 -c "../$SRC" -o /dev/null -fdump-lang-class=- 2>/dev/null | head -40

echo; echo "=== 5. ODR 检查 ==="
[ $# -gt 0 ] && g++ -std=c++17 -O2 -flto -Wodr "../$SRC" "$@" -o odrcheck 2>&1 | head -20

echo; echo "=== 6. UB 检测 (ASan+UBSan) ==="
g++ -std=c++17 -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer \
    "../$SRC" "$@" -o san 2>/dev/null && ./san 2>&1 | head -30

echo; echo "=== 7. -O0 vs -O2 汇编对比 ==="
g++ -std=c++17 -O2 -S "../$SRC" -o - 2>/dev/null | grep -E '^\t(jmp|call)\s+\*' \
  && echo "  ↑ 上面是间接跳转（动态派发）" \
  || echo "  无间接跳转（可能已去虚化/内联）"
```
