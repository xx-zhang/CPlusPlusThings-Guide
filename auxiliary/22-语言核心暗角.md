## 1 · 名字查找：三段 + ADL

### 1.1 三段查找（顺序不可逆）

```text
非限定名查找（unqualified）：块作用域 → 外层 → 类/基类 → 命名空间 → 全局   ← 找到即停，不再往外看
限定名查找（qualified）：   A::b::f —— 只在指定作用域里找
ADL（实参依赖查找）：       对函数调用，额外到「实参所属的命名空间」里找同名函数
```

**ADL 是运算符重载与 `swap` 惯用法的基础**——实测：

```cpp
namespace my { struct S { int v; }; void swap(S&, S&) noexcept; }
my::S a{1}, b{2};
swap(a, b);      // 没写 my::，靠 ADL 找到 my::swap ✅ 实测输出 2 1
```

**这就是为什么泛型代码写 `using std::swap; swap(a,b);`**——若不 `using`，`std::swap` 根本不可见（ADL 只找实参所在 namespace，不含 `std`）。

### 1.2 名字隐藏 ≫ 重载（专家最容易踩的静默陷阱）

**规则**：派生类里只要有同名函数，基类的**所有同名重载**都被隐藏（除非 `using Base::f;`）。

**实测（静默选错，不是编译错误！）**：

```cpp
struct B { void g(int); void g(double); };
struct D  : B { void g(int); };              // 隐藏了 B::g(double)
struct D2 : B { using B::g; void g(int); };  // 恢复 B::g(double)

D  d;   d.g(1.5);   // → 实测输出 D::g(int)      ← 静默把 double 转成 int！
D2 d2;  d2.g(1.5);  // → 实测输出 B::g(double)
```

**这是最危险的一类 bug**：编译通过、语义变了。**审代码时看到派生类定义同名函数，立刻检查是否有 `using`。**

## 2 · 重载决议：四步与三类陷阱

### 2.1 四步（记住顺序）

```text
① 收集候选（名字查找 + ADL 的结果）
② 筛出可行（实参个数/类型能转换过去）
③ 排序（转换序列的等级）：精确匹配 > 提升 > 转换 > 用户定义转换 > 省略号
④ 取最优；有并列 → 歧义（编译错误）
```

### 2.2 陷阱一：顶层 const 不影响重载

```cpp
void f(int);        // 这两个是同一个函数
void f(const int);  // ← 重复声明，不是重载
```

**原因（T1）**：`const` 修饰的是类型读权限，而参数的顶层 const 在**调用方**看不出差别（实参都是拷贝）。**底层 const 才影响**：`void f(int*)` vs `void f(const int*)` 是重载。

### 2.3 陷阱二：`0` 是歧义源（实测）

```cpp
void f(bool);  void f(void*);
f(0);       // ❌ 实测：error: call of overloaded 'f(int)' is ambiguous
f(nullptr);// ✅ 实测输出 f(void*)   ← nullptr 有类型（nullptr_t），不歧义
```

**这就是 `nullptr`（C++11）存在的全部理由**——不是"更好看"，是**消除歧义**。

### 2.4 陷阱三：引用限定符与 `const` 决定"对象身份"

```cpp
struct S {
  void f() &;    // 只能对左值对象调用
  void f() &&;   // 只能对右值对象调用（可偷资源）
  void f() const;// const 对象只能调这个
};
```

**这是 `std::optional`/`std::string` 等库区分「取副本」和「偷资源」的机制**，读库源码必懂。

## 3 · 初始化动物园（AI 代码最常错的地方）

### 3.1 关键差别：`{}` 拦截窄化，`()` 放行（实测）

```cpp
double d = 3.9;
int a(d);      // ✅ 实测：允许（静默截断）
int b{d};      // ⚠️ 实测：非 const 报 warning（-Wnarrowing），加 -Werror=narrowing 即错误
int c{3.9};    // ❌ 实测：常量 → 硬错误 error: narrowing conversion
int e{3};      // ✅ 可精确表示 → 通过
```

**专家规则**：**默认用 `{}` 初始化**（能拦窄化、能防 MVP、天然值初始化）。只有需要调 `initializer_list` 语义明确时才用 `()`。

### 3.2 Most vexing parse（实测有专门告警）

```cpp
Widget w();    // 实测：warning: empty parentheses were disambiguated as a function declaration
               // 这不是对象！是函数声明
Widget w{};    // ✅ 对象
Widget w;      // ✅ 对象（默认初始化——但对 class 类型是"不初始化成员"！）
```

### 3.3 三种"没写初始化"的区别（专家必分清）

```text
T x;         默认初始化：内置类型成员是**未初始化**（读=UB）；class 类型调默认构造
T x{};       值初始化：内置类型**置零**；class 类型调默认构造
T x = T();   同值初始化
static T x;  静态存储期 → **零初始化**（读它有定义）
```

**推论**：`T* p = new T;` 与 `new T()` 不一样（前者内置成员未初始化）。**这是"未初始化读"UB 的常见来源（08 §1.7 第④条）。**

### 3.4 聚合 vs 构造函数（`{}` 走哪条路）

```text
有用户提供的构造函数 → {} 调构造函数（成员按函数体走）
无构造函数、无非 public 成员、无基类虚函数、无 NSDMI（C++11 口径）→ 聚合初始化：按**声明顺序**逐成员
聚合 + {} → 未列出的成员**被值初始化（置零）**——这是最安全的默认
```

## 4 · ODR 与 ABI（细节见 19，这里给专家的判据）

```text
ODR 判据：这个定义会不会出现在多个 TU？（A1）
  · 头文件里的普通函数/全局变量 → 违反（violations 见 lessons/01）
  · inline/模板/constexpr/类内成员 → 豁免（弱符号 W）
ABI 判据：这个改动会换二进制接口吗？
  · 加/删成员、改继承、改虚函数顺序、改模板签名、改 inline 与否 → 会
  · 加**非虚**成员函数、改函数体 → 不会
不完整类型（incomplete type）：
  · unique_ptr<T> 的析构需要**完整类型 T**（要 delete）→ pImpl 必须在 .cpp 里写析构
  · shared_ptr 不需要（类型擦除的 deleter）→ 这是两者在头文件设计上的关键差别
```

## 6 · 自测三问

- **判定**：`struct D : B { void f(int); };` 里 `d.f(1.5)` 会调谁？（`D::f(int)`——`B::f(double)` 被隐藏，静默转换；要 `using B::f;`）
- **预测**：把 `f(0)` 改成 `f(nullptr)`，`void f(bool)/void f(void*)` 会选哪个？为什么 `0` 不行？（选 `void*`；`0` 是 `int`，两种转换都不占优 → 歧义）
- **构造**：写一个类，让它只在右值上提供可偷资源的接口（`f() &&` vs `f() &`），并验证左值调用被编译器拒绝。
