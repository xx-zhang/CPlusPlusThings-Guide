## 0 · 这个体系解决什么问题

- 「`-O0` 469ms，`-O2` 138ms」（本机实测 3.4 倍）——优化等级本身就是第一档性能开关

## 1 · 核心原则

### 1.1 三个"免费"的性能开关（顺序做，别跳）

```text
① 编译选项：-O2（默认）+ -march=native（本机 ISA）+ -flto（跨 TU 内联/去虚化）
② 算法/数据结构：复杂度由一个布局决定（10 §1.1）——先改结构再抠指令
③ 让编译器看得见：把类做成 noexcept move（09 §1.2）、final（去虚化）、constexpr（编译期算）
```

**实测锚点**：`final` 引用参数照常完全去虚化（08：`movl $3,%eax`）；没写 `inline` 的函数 `-O2` 照常内联。

### 1.2 内存的三个层次：布局、局部性、分配

**① 布局（A3）**——同样的字段，顺序决定 `sizeof`（实测 08：`class B:A` 是 24，无重排；想省空间自己重排字段或 `alignas`）。**对齐填充是浪费的常见来源**：`char,double,char` = 24；`char,char,double` = 16。**CAE 结构体字段多，排上个 10% 的空间是常事。**

**② 局部性（缓存）**——连续内存是所有缓存性能的基础：

```text
安 S.oA（数组的结构）：std::vector<Point> pts;    // 常用；每个元素凑在一起
SoA（结构的数组）：     double xs[N], ys[N];       // 向量化友好；按字段连续
```

**遍历全部元素做单字段运算 → SoA 赢；偏随机访问单元素 → AoS 赢。别猜，用 05 §10 测。**

**③ 分配**——堆分配比栈慢两个量级（malloc/free 系统调用 + 锁）。对策：

```text
· vector.reserve() 预分配（扩容 2 倍搬移已实测 08）
· 复用缓冲区（成员 vector 保留 capacity）
· 对象池 / arena：CAE 大量小对象时，一次大块分配 + 复用
· 栈优先：小对象直接值成员，别 new
```

### 1.3 虚调用、内联、去虚化（A4/T5）

```text
虚调用 = 一次间接跳转（编译器不可内联）；
编译器能证明动态类型（实际对象/final/LTO/推测去虚化）→ 消除
```

- 热路径上的多态：优先 `final` + 值语义（别到处 `shared_ptr<Base>`）；或改静态多态（CRTP，12 §1.3）。
- 别为了"多态"把本来编译期固定的分派做虚——那是元原则 3 的违犯。

### 1.4 不要为性能写的四件蠢事（会写错语义）

| 蠢事 | 后果 | 正解 |
| --- | --- | --- |
| `std::move` 返回局部对象 | **阻止 NRVO**（08 已录结论） | 直接 `return v;` |
| 做大对象裸指针传参 | 语义不清 + 悬垂 | `const&`/`span` |
| 微基准论英雄 | 拿 10us 的实验给宏优化 | 先全局测（perf/计时），再热点微调 |
| 未 init 变量 + 期望"快" | UB（A2） | 初始化；编译器该快的它自己会快 |

## 2 · 知识点地图（离散点）

| 点 | 一句话关键 | 注意 |
| --- | --- | --- |
| 存储期四值 | automatic/static/thread/dynamic（A3） | 栈 vs 堆 vs 静态区 |
| 对齐/填充 | `alignof`/`alignas`；填充决定 sizeof（08：24/16 实测） | 字段排序省空间 |
| 分配开销 | malloc/free 大开销；`new` 亦然 | reserve/复用/池 |
| 缓存局部性 | 连续访问 ↔ 顺序遍历最友好 | AoS vs SoA |
| 虚拟内存 | 大数组 = 页表 + 缺页；首次访问未触碰页慢 | 预热/预分配 |
| 内联 | 优化器决定；`inline` 关键字不是开关（08） | 看汇编 `-S -O2` |
| 去虚化 | `final`/`-flto`/推测去虚化（08 汇编） | 热路径多用 final |
| 向量化/SIMD | 编译器自动向量化需连续 + 无别名；`-O3 -march=native`，`llvm-mca` 看吞吐 | SoA 更友好 |
| 编译期计算 | constexpr 表/分支——运行期零成本（元原则 3） | static_assert 校验 |
| 超线程/NUMA（延伸） | 并行时的内存亲和 | 领域深水，先别急 |

## 3 · 决策流程：性能调优五步（先测后调）

```text
① 测量：确定"慢在哪"——perf/time/计时，找到热点函数与热点行
     （本机 perf 硬件计数器不可用 → perf stat 的时间指标 + 应用内计时）
② 假设：从数据/布局/分配/虚调用四个方向提出一个可证伪的假设
③ 验证：改一处 → 重测 → 看假设是否成立（一次只改一处！）
④ 归档：把"为什么"写进 08 反例档案（不然下个月又忘了）
⑤ 停止：收益未证明就停；别为"可能快"添加复杂度（元原则 1 反向）
```

```text
热路径清单（照此过一遍，很多性能问题其实就这五条）：
□ 优化等级 -O2/-O3 -march=native -flto 开齐了吗？
□ 数据结构选对了吗？（布局决定复杂度）
□ 分配热点有 reserve/复用/池吗？
□ 类都可以 noexcept move / final 吗？（观察汇编）
□ 有没有在热路径里做拷贝、建 string、打日志？
```

## 4 · 常见坑（AI 代码高频）

| 坑 | 症状/原因 | 修法 |
| --- | --- | --- |
| `std::endl` 刷缓冲 | 每次 flush，I/O 慢 | `'\n'` |
| 字符串拼接 `s += std::to_string(x)` | 反复分配 | `std::ostringstream` 或先 reserve |
| `for(auto x : v)` 拷贝 | 每次拷贝元素 | `const auto&` |
| 热路径 `new` 循环里建对象 | 分配爆炸 | 复用/栈/值成员 |
| 大对象按值传参 | 深拷贝 | `const&` / span |
| 虚调用不可去虚化 | 每次间接跳转 | final / 值语义 / CRTP |
| 微优化 over 算法 | 改了指令没改结构 | 先结构后指令（§1.1-②） |
| 没测就"优化" | 修了不热的地方 | 五步法的第 ① 步不能跳 |
