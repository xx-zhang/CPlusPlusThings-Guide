# 12 · 模板与泛型体系

> **场景**：读不懂 AI 生成的模板代码、SFINAE 像咒语、`std::enable_if` 满天飞、模板定义被塞进 `.cpp`。
> **挂靠**：A4（编译期分层）· T7（值类别/转发）· 元原则 3｜**学**：04 第 12 课 · 07 图谱⑥⑦｜**记**：08 定理钩子 T7

## 0 · 这个体系解决什么问题

模板是 C++ 里**最容易被"会写不会读"的部分**。这个体系让你：

1. 把模板当成**编译期类型函数**（输入类型 → 输出类型/值），读法就顺了；
2. 知道 SFINAE / concepts / if constexpr 各自解决什么；三层递进，够用即可；
3. 看懂并修正 AI 生成的模板问题（最常见：定义放 `.cpp`、滥用 enable_if、用错转发）。

## 1 · 核心原则

### 1.1 模板 = 编译期类型函数（A4）

> 函数：`f(实参) → 值`。模板：`T(类型实参) → 类型/函数`。**一切发生在编译期；实例化后运行期零成本。**

```text
template<class T> T add(T a, T b);   // 类型函数：int → 函数 add(int,int)；double → add(double,double)
```

读模板的三步：**① 它是谁（函数模板/类模板/别名模板）→ ② 输入是什么（类型参数/非类型参数/模板参数）→ ③ 输出是什么（函数？类？类型？）**。能回答这三问，一段陌生模板代码就读懂一半。

### 1.2 为什么要 header-only（A1 的直接推论）

模板**在实例化点才展开**，编译器必须看到**完整定义**。所以：

- 定义必须在头文件（且被所有使用者可见）——**放到 `.cpp` 会导致 `undefined reference`**（最常见的 AI 模板错误）。
- 模板实例是**弱符号 `W`**（实测 nm），多个 TU 各实例化一份、链接器合并——所以不违反 ODR。
- 替代方案：**显式实例化**（`template class Matrix<double>;` 放 .cpp，其它 TU 声明）——库交付或编译时间敏感时用。

### 1.3 三层"类型级分支"（递进，选够用的）

| 机制 | 年代 | 干什么 | 什么时候用 |
| --- | --- | --- | --- |
| 重载 + 特化/偏特化 | C++98 | 按类型或模板实参的形态选实现 | 经典泛型算法 |
| **SFINAE**（`enable_if`/`void_t`） | C++11 | **替换失败不是错误**——候选不匹配就丢弃换下一个 | 按"类型是否支持某操作"选：表达式 SFINAE、is_* 检测 |
| **`if constexpr`** | C++17 | 实例化时**只编译选中的分支** | 同一定义内按类型走不同代码，可读性最好 |
| **Concepts/`requires`** | C++20 | 给类型参数**显式约束**，报错信息好、重载规则干净 | 新代码优先用；replace `enable_if` |

> **读 SFINAE 的口诀**：整个 `<type_traits>` 都是「问这个类型是不是 X」的编译期谓词；`enable_if<条件, T>` 在条件假时**不提供这个重载**，于是重载决议换下一个——这就是"替换失败不是错误"。

### 1.4 一个被严重误解的词：`std::move` 与 `std::forward`（T7）

```text
std::move(x)   = static_cast 成右值引用：让"重载/移动构造"有机会被选中。它不移动任何东西。
std::forward<T>(x) = 在转发引用里还原 x 原本的值类别。它不是转换，是"还原"。
```

- **`std::move` 用在 const 对象上** ⟹ 拷贝不是移动（const 剥夺了移动）——AI 经常写错。
- 万能引用只在 `template<class T> void f(T&&)` 且 `T` 被推导时成立；固定类型 `void f(int&&)` 不是万能引用。

## 2 · 知识点地图（离散点）

| 点 | 一句话关键 | 注意 |
| --- | --- | --- |
| 函数模板/类模板/别名模板 | 三种模板；别名模板（`using V=...`）不能特化 | `template<typename vs class>` 等价（历史） |
| 类型参数 / 非类型参数 / 模板模板参数 | 非类型：`template<int N>`（编译期常量）；模板模板：`template<template<class> class C>` | 非类型参数可作数组上界 |
| 推导 | `T` 从实参推导：去引用、去 cv（顶层）、数组衰减为指针 | **引用折叠**只在推导期出现（T7） |
| 万能引用 / 完美转发 | `T&&` 推导 + `forward<T>` | 见 1.4 |
| 显式实参 | `f<int>(x)`；类模板 C++17 起可 CTAD（`std::pair{1,2}`） | CTAD 与推导指引 |
| 特化 / 偏特化 | 特化：全部参数；偏特化：部分（类模板专用） | 函数模板不能偏特化（用重载） |
| 可变参数 / 折叠 | `template<class... Ts>`；`(args + ...)` 折叠表达式（C++17） | 递归 vs 折叠：折叠可读性最好 |
| SFINAE | 替换失败不是错误（见 1.3） | `void_t` 探测技巧 |
| type traits | 编译期谓词：`is_same/is_integral/is_copy_constructible/is_constructible` | L3 查表 |
| `if constexpr` | 实例化期分支，未选分支**不实例化**（所以说它"编译期 if"） | 比 enable_if 可读得多 |
| CRTP | `class D : public Base<D>`：基类用派生类型（编译期多态，T5 第 2 层） | 静态多态 = 零间接跳转 |
| Concepts（C++20） | `template<std::integral T>` / `requires` 约束与重载细化 | 代替 enable_if 报错更友好 |
| 模板与头文件 | 定义必须可见（1.2）；显式实例化替代 | 最常见的 AI 错误 |

## 3 · 决策流程：怎么读懂/修正一段模板代码

```text
读懂：
 ① 它是哪一种模板？输入输出是什么？（1.1 三问）
 ② 有没有分支？（特化/enable_if/if constexpr/concept）每一支在什么类型上生效
 ③ 有没有转发？（move/forward）传进来的东西最终被当左值还是右值用
编译不过？
 ④ 报错在实例化点 → 看是不是"定义不可见"（.cpp 里）——先查这个
 ⑤ 报错在重载决议 → 找 enable_if/concept 的约束，是不是类型没满足
写得更好？
 ⑥ 能用 if constexpr / concept 的地方别用 enable_if（可读性）
 ⑦ 别为"可能"的特例过度模板化——先写具体版本，出现第二个使用者再泛化
```

## 4 · 常见坑（AI 代码高频）

| 坑 | 症状/原因 | 修法 |
| --- | --- | --- |
| 模板定义放 `.cpp` | `undefined reference`（A1） | 移回头文件；或显式实例化 |
| `std::move` 用在 const 上 | 变成拷贝（T7） | 检查被 move 对象是否 const |
| `std::forward` 用在非转发引用上 | 语义错误 | 只在 `T&&` 推导处用 forward |
| `enable_if` 读不懂 | 约束 + 条件混在签名里 | 换 `requires`/concept；或别名提取条件 |
| 过度模板化 | 泛化的泛化，维护噩梦 | 先具体后泛化（§3 ⑦） |
| 递归可变参数模板 | 编译慢、难读 | 折叠表达式（C++17） |
| 忽略模板实参推导失败 | 报错信息轰炸 | concepts（C++20）后报错定位明显改善 |
| `typename` 忘写在依赖类型前 | 编译错误：`need 'typename' before ...` | 带依赖类型 `typename T::value_type` |
| 把类模板实例当类型用 | `Matrix<int>` 是类型，`Matrix` 不是 | CRTP/模板模板参数的场景才直接用 `Matrix` |

## 5 · 实践关联（动手清单）

```bash
# ① 验证「模板 = 弱符号 W + header-only 才可见」（08 已录）
g++ -std=c++17 -c /tmp/l1check/t7.cpp -o t7.o && nm -C t7.o | grep cube   # → W int cube<int>(int)

# ② 复现"定义放 .cpp"的链接错误（lessons/01 的实验 4）
# ③ 用 if constexpr 消灭一段 enable_if：两个版本对比可读性
# ④ 验证 std::move 在 const 上 = 拷贝
g++ -std=c++17 -fsyntax-only -x c++ - <<'EOF'
#include <string>
#include <type_traits>
void f(std::string&&) {}
int main(){
  const std::string s("x");
  // f(std::move(s));   // ❌ move 后仍是 const string → 匹配不到 string&&
  using T = decltype(std::move(s));
  static_assert(std::is_same_v<T, const std::string&&>, "move(const) 得到 const&&");
}
EOF
```

## 7 · 自测三问

- **判定**：`template<class T> void f(T&&)` 里传 `int&` 时 `T` 推导成什么？（`int&`——引用折叠出 `int&`）
- **预测**：把模板定义从头文件挪进 `.cpp`，其它 TU 使用时链接会报什么？显式实例化怎么救？
- **构造**：用 `if constexpr` 写一个「整数走整除、浮点走相除」的函数，并编译期验证两个分支只有一个实例化。
