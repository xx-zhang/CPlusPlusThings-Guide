# auxiliary · C++ 知识框架与学习手册

> 这是 `CPlusPlusThings` 仓库**之外**的一层脚手架。
>
> 仓库给你 **95 张知识点卡片**（「XX 那些事」）；
> 这个目录给你**把它们串起来的那根绳**（公理 → 定理 → 主题），
> 以及**基于这根绳的实证学习方法**（怎么确认一张卡片是对的、怎么把它变成能力）。

---

## 0. 30 秒看懂这两套东西的区别

| | `CPlusPlusThings` 仓库 | 本目录 |
| --- | --- | --- |
| 组织方式 | 主题 → 结论 → 一段代码 | 公理 → 派生定理 → 映射到主题 |
| 回答的问题 | 「`sizeof` 是 8 字节」 | 「**为什么必然**是 8 字节，什么条件下会变」 |
| 知识形态 | **岛屿**（95 个孤立结论） | **大陆**（5 条公理推出全部结论） |
| 可靠性 | 结论多半对，**推理经常错**（见 `06`） | 每条都标注了实测命令与出处 |
| 你拿走什么 | 素材、反例、索引 | 可推理的判断力、可复用的验证方法 |

**一句话**：仓库告诉你「是这样」；本目录告诉你「**为什么必然是这样**」，以及「**怎么亲手确认它就是这样**」。

## 2. 建议的阅读顺序

### 第一遍 · 建骨架（约 40 分钟，**不碰仓库代码**）

1. `01-知识框架.md` 通读，**先读它的「第 0.5 层 · 元公理」**；若觉得「公理」牵强，立刻加读 `00-方法论自检与迁移.md`（推导角度、自验协议、已知张力）。然后只求能画出「世界/语义/翻译/时机」那张图，不追求细节。
2. `07-场景体系总览.md` 扫一眼第 1 节总图谱（建立「知识长在哪」的地图感，细节后补）。
3. `02-正交轴与术语速查.md` 的**第一张表和第二张表**（三把尺子 + 四元组）背下来。
4. `03-学习方法与步骤.md` 读一遍，把六步法的六步名字记住。

**第一遍的验收标准**：给你仓库里任意一篇「那些事」，你能说出它挂在**哪条公理/定理**上。

### 第二遍 · 对账（每个主题 15~30 分钟）

对每一个你关心的主题，走一遍 `03` 里的六步法：
> **定位 → 预测 → 实测 → 对账 → 反例 → 归档**

重点读 `06-仓库审计报告.md` 的对应条目——**别人踩过的坑，成本最低的收获**。

### 第三遍 · 构造

不再按仓库目录顺序走，改按 `04-学习路线图.md` 的**14 课**走。
每一课都要求你自己**构造一个仓库里没有的反例**。构造不出来 = 还没掌握。

## 3. 三条使用约定（重要，读完请照做）

### 约定一：任何结论先当「假设」，不当「事实」

仓库里的每一句解释，包括那些看起来权威的（带汇编、带 gdb 输出的），**都要亲手验证一遍**。
成本极低——`05-实验工具箱.md` 里 90% 的验证不超过 3 行命令。

已验证的案例：仓库 `sizeof/README.md` 说 `sizeof(B)` 是「16 或 24，可能被编译器优化重排」，实测**就是 24，没有重排**。

### 约定二：只信仓库的「代码」和「现象」，对「解释」保持怀疑

仓库的价值在于它提供了 **435 个能跑（或故意跑不通）的 .cpp 文件**——这是真金白银的素材。
但它的「解释」段落经常是二手转述，**结论对、推理错**。而推理错了，遇到变体就会翻车。

### 约定三：每个主题学完，必须留下三行笔记

```markdown
## 主题：<名字>
- 原则：<一句话，挂在哪条公理/定理上>
- 前提：<这条原则在什么条件下不成立>
- 反例：<我自己构造的、仓库里没有的失败案例>
```

**没有第三行，就不算学过。**

## 4. 与你的学习目标对齐

你的目标不是成为 C++ 专家，而是**读懂、修改、审查 AI 生成的 C++ 代码**（CAE/EDA 方向）。

| 你的需求 | 本手册哪一部分直接解决 |
| --- | --- |
| 「AI 生成的代码编译不过 / 链接不过」 | `lessons/01`（翻译单元与链接）+ `01` 的 A1 |
| 「同一个 bug 修了又在别处冒出来」 | `01` 的 A3（对象四元组）——同一个根因的四个切面 |
| 「`-O0` 正常、`-O2` 结果变了」 | `01` 的 A2（抽象机与 UB）+ `04` 第 3 课 |
| 「AI 用了一堆模板 / 移动语义，我看不懂」 | `01` 的 A4 + T4 + T7；`04` 第 6/12 课 |
| 「我不知道该怀疑哪一行」 | `03` 的「面向审 AI 代码的分层检查流程」 |
| 「怎么确认 AI 说的对不对」 | `05-实验工具箱.md` |

## 5. 关于本目录的可靠性

- 本目录所有技术结论，**要么标注了实测命令与真实输出，要么标注了标准条款**。
- 存疑处一律显式标注「存疑」或「实现定义」，**不做无根据的断言**。
- 环境：`g++ 14.2.0 (Debian)` / `clang 19.1.7` / x86-64 Linux。凡涉及**布局、汇编、vtables 的结论都是 ABI 相关的**——换编译器/平台需重测（`05` 里给了重测命令）。
