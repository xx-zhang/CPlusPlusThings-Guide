# 25 · 专家练习路径（把材料变成能力的引擎）

> **残酷前提**：材料到此已齐（00-24）。**读完全部 ≠ 成为专家**——瓶颈从来不是资料，是**刻意练习的闭环**。
> 本文件是唯一一篇「要求你动手」的文档：**读什么、写什么、测什么、审什么，以及怎么知道自己在进步。**
>
> **挂靠**：03（六步实证法）· 21 §2.4（L1-L4 成熟度）· 08（记忆卡 + 反例档案）

---

## 0 · C++ 专家的四级成熟度（自评标尺）

| 级 | 表现 | 判据（对 C++） |
| --- | --- | --- |
| **L1 会描述** | 能复述规则 | 「`inline` 是放宽 ODR」——能说 |
| **L2 会预测** | 给定代码能预测行为/编译结果 | 看到 `d.g(1.5)` 能立刻说出调哪个（22 §1.2） |
| **L3 会解释** | 能解释故障根因、能定位到哪一层 | 崩了/慢了/偶尔错 → 知道先上哪个工具（14） |
| **L4 会改进** | 能改设计并**证明**改得更好 | 优化后有基准数据；重构后 ABI/语义可控（13/24） |

> **大多数人的天花板在 L2→L3**：会背、能预测，但**遇到真实故障无法定位**。突破口只有一个：**做故障，然后抓它**。

## 1 · 刻意练习四环（每环都有产出物）

```text
读 → 写 → 测 → 审
↑                  │
└── 反例档案（08）←─┘
```

| 环 | 做什么 | 产出物 | 时长/次 |
| --- | --- | --- | --- |
| **读** | 读标准库实现与真实项目 | 一份「源码笔记」（机制 + 我原以为 vs 实际） | 60~90 min |
| **写** | 重造轮子（下 §3） | 可编译、有测试的代码 | 2~4 h |
| **测** | benchmark + sanitizer + 交叉编译器 | 数据 + 反例 | 30 min |
| **审** | 用 03 五层流程审真实代码（含 AI 生成） | 审查报告（05 模板） | 30 min |

**频率建议**：每周 2 个完整循环（约 6~8 小时）。**12 周 = 24 个循环**，足以把 L2 推到 L3。

## 2 · 读：源码清单（读法比书单重要）

**必读顺序（由浅入深，都在本机 `/usr/include/c++/14/` 或 libc++ 里）**：

| # | 文件 | 读什么（带着问题） |
| --- | --- | --- |
| 1 | `bits/unique_ptr.h` | 怎么做到零开销？`default_delete` 与 EBO（01 A3） |
| 2 | `bits/shared_ptr_base.h` | 控制块结构、原子计数、`weak_ptr` 怎么不增计数 |
| 3 | `bits/stl_vector.h` + `vector.tcc` | 扩容策略、`noexcept` 移动分支（08 实测）、迭代器失效 |
| 4 | `bits/allocator_traits.h` | traits 怎么把「可选能力」探测出来（12 §1.3） |
| 5 | `bits/basic_string.h` | SSO 阈值、COW 的历史、`operator[]` 与 `at()` 的差别 |
| 6 | `bits/optional.h` | 手工 lifetime 管理（placement new + 析构）、`&&` 重载 |
| 7 | `string_view` | 借用语义与生命周期陷阱（23 §2） |
| 8 | `bits/std_function.h` | 类型擦除、SBO（小对象优化）、为什么它慢 |

**读法（三步，别通读）**：

```text
① 先猜：如果是我，怎么实现？（写下你的设计）
② 再读：它怎么实现的？哪里和我想的不一样？
③ 记：差异处就是收获 → 写进 08 反例档案（我的设计 vs 实际设计）
```

## 3 · 写：重造轮子清单（8 项，每项有验收标准）

> **原则**：不写完不看答案。写完再对照标准库（那时你才看得懂为什么那样写）。

| # | 写什么 | 验收标准（必须全过） |
| --- | --- | --- |
| 1 | `my_vector<T>` | copy/move 正确（rule of 5）· `noexcept` 移动 · 扩容 2 倍 · 迭代器失效行为与 std 一致 |
| 2 | `my_unique_ptr<T>` | 零开销（`sizeof` 等于裸指针，用 05 §4 验证）· 支持自定义 deleter · 无可拷贝 |
| 3 | `my_shared_ptr<T>` | 控制块独立分配 · 计数原子 · 无循环引用泄漏（ASan 验证） |
| 4 | `my_optional<T>` | 手工 lifetime（placement new/析构）· `&&` 重载偷资源 · 空状态不构造 T |
| 5 | `my_small_string`（SSO） | ≤15 字节不分配（用分配计数器证明）· ≥16 字节正确搬移 |
| 6 | `my_allocator` + `monotonic` 池 | 与 `vector` 配合 · 池让分配次数下降一个量级（测出数据） |
| 7 | `type_traits` 三件套 | 自己实现 `is_same`/`enable_if`/`void_t` 探测「有 `size()` 吗」 |
| 8 | `spsc_ring<T>` | 单生产者单消费者无锁 · TSan 干净 · 容量为 2 的幂 · 无分配 |

**第 8 项是具身智能的直通车**（18 §1.2 的 intra-process 底层形态）。

## 4 · 测：每次写完必做的四件事

```bash
# ① 正确性：单测 + sanitizer（ASan/UBSan 必开）
g++ -std=c++20 -g -O1 -fsanitize=address,undefined test.cpp -o t && ./t
# ② 并发：TSan（第 8 项 spsc_ring 必须）
g++ -std=c++20 -g -O1 -fsanitize=thread -pthread t.cpp -o t && setarch $(uname -m) -R ./t
# ③ 性能：与标准库对比（先测后调，13 §3）
#    用 -O2，跑 3 次取中位数；记录数字进 08
# ④ 交叉验证：clang++ 再编一遍（布局/汇编结论必须双编译器）
clang++ -std=c++20 -O2 -S your.cpp -o - | head -40
```

## 5 · 审：把「读」变成「判断」

**素材**：① AI 生成的代码（你最真实的场景）② 开源项目 PR ③ 标准库某个函数的实现。

**方法**：`03` 第五节的五层流程（工具 → 类型约束 → 四元组 → 值类别 → UB），**输出固定格式审查报告**。

**进阶练习**：拿 `06-仓库审计报告.md` 里的 33 条错误，**自己先判断再翻我的结论**——命中率就是你的进步曲线。

## 7 · 里程碑检查点（可验证，不靠感觉）

```text
□ M1（第 4 周）能不看文档写出 rule of 5 正确的类，并用 nm/汇编证明移动生效
□ M2（第 7 周）实现的两个智能指针通过 ASan 无泄漏；能解释控制块与计数器

□ M4（第 11 周）对一个真实慢函数做完五步调优，有前后基准与机制解释
□ M5（第 12 周）审一份陌生代码，能定位 ≥3 个真实问题（其中至少 1 个是 UB 或 ODR）
```

**达到 M1-M5 = L3（会解释）；能持续 L4（改进并证明），就是专家。**

## 8 · 常见弯路（省你半年）

```text
✗ 只读不写 → 停在 L1，且会产生"我懂了"的错觉
✗ 只写不测 → 写出"能跑但错"的代码，L2 都到不了
✗ 追新特性 → 用不到 C++23 的 mdspan 却不会写 rule of 5
✗ 收藏资料 → 你现在这套 25 篇已经够用，再收藏就是拖延
✗ 跳过基准 → "优化"变玄学（13 §3）
✗ 只在 -O0 调试 → 漏掉 -O2 才暴露的 UB（14 §1）
✗ 不写反例 → 一个月后忘光（08 §3 的全部意义）
```

## 9 · 反馈回路（这是"快速"的唯一来源）

```text
每个循环：读/写 → 测 → 发现差异 → 写进 08 反例档案 → 次日回看 → 修正
每周：08 必背清单抽查 5 项 + 危险信号八项过一遍
每月：重跑一次 M1-M6 里程碑，看哪项退化了
```

> **六步实证法（03）就是这条回路的发动机**：定位 → 预测 → 实测 → 对账 → 反例 → 归档。
> 而**「对账」产生的差异，就是你成长的唯一来源**——不是读了多少，是**纠正了多少次自己的错误预测**。
