# 19 · 构建与插件体系

> **场景**：把一个 C++ 代码库变成 ROS2 包（ament/colcon）、用 pluginlib 做动态加载插件、跨 .so 的符号与 ABI 问题。
> **挂靠**：A1（翻译单元/ODR 在二进制层的延伸）｜**记**：本体系大部分是 **L3 现查**——记住"原理 + 在哪查"，不背命令

---

## 0 · 这个体系解决什么问题

- 代码单独编译没问题，一进 colcon 就 `undefined reference` / `multiple definition`
- pluginlib 插件加载失败（符号找不到）
- 换一个包版本，A 包就不认识 B 包的类了（ABI 断裂）

**一条主线贯穿全部**：**「A1 翻译单元公理」从"编译期"延伸到"链接期 + 运行期（dlopen）"**——模块边界就是符号边界，ODR 从"一个程序"扩展到"一组动态库"。

---

## 1 · 核心原则

### 1.1 编译 → 链接 → 加载：三个阶段，三个符号问题

```text
编译期：每个 TU 独自检查（A1）→ 报错=语法/类型
链接期：把 .o 拼成可执行文件/动态库 → 报错=undefined/multiple definition（08 符号表）
运行期：dlopen 动态库、按名字找符号 → 报错=plugin 找不到 / 符号找不到（类似链接期，但是运行时报）
```

**插件 = dlopen 的产物**：pluginlib 的本质就是"给定一个基类接口 + 一个 .so，运行时按名字 `dlopen` 并构造派生类"。所以查"插件加载失败" = 查「符号是否被导出 + 名字是否匹配」。

### 1.2 符号导出与可见性（AI 代码最常踩的动态库坑）

```cpp
// 默认情况下 Linux 上 .so 的所有符号都导出（COM 上要显式 __declspec(dllexport)）
// 好习惯：-fvisibility=hidden + 显式导出宏
#define MYLIB_PUBLIC __attribute__((visibility("default")))
class MYLIB_PUBLIC MyApi { ... };   // 只导出你想让外面用的
```

**为什么 ODR 在 .so 之间还会炸**：两个 .so 都定义同名强符号（或同一头文件里有普通函数定义）→ 加载时符号冲突/互相覆盖。**解决办法和 A1 完全一致：`inline`/匿名 namespace/只放在一个 TU。**

### 1.3 ABI：为什么"换编译器/换发行版就得重编所有依赖"

```text
ABI = 二进制接口（类布局、名字修饰、异常机制、std::string 内部）
ROS2 每个发行版(Foxy/Humble/Jazzy…)锁死一套 ABI → 混合版本 = ODR/布局错乱
换编译器、加 -DNDEBUG 变化、标准库实现不同 → ABI 可能变
教训：永远同一发行版 + 同一编译器编译所有包
```

## 2 · 知识点地图（离散点，L3 为主）

| 点 | 一句关键 | 查/记级别 |
| --- | --- | --- |
| colcon build | ROS2 构建前端（并行编译多个包） | L3（命令现查） |
| ament_cmake | 包的类型与导出宏（`ament_export_dependencies`） | L3 |
| `CMakeLists.txt` 最小集 | `add_executable`/`add_library`/`target_link_libraries`/`install(TARGETS ...)` | L3（有个模板在手即可） |
| 头文件/include 路径 | 包内 include 目录 + 导出 include | L3 |
| pluginlib | 基类接口 + 插件描述 xml + 注册宏 + `dlopen` | **L2**（原理见 1.1） |
| `dlopen`/`dlsym`/`dlclose` | 运行期加载/找符号/卸载 | L2（底层机制） |
| 符号可见性 | `-fvisibility=hidden` + 导出宏（1.2） | **L2（必背思路）** |
| mangled 符号 | 重载=名字不同（`nm -C` 可读，08） | L2（用 nm 查） |
| 静态库 vs 动态库 | 静态=链接期并进可执行文件；动态=运行期加载 | L2 |
| ABI 稳定性 | 同发行版同编译器（1.3） | **L1（一条铁律）** |
| `rclcpp::init` | 每个进程一次，线程安全初始化 | L3（ROS2 事实） |
| export/include 不洁 | 包 A 编译时把内部符号泄给 B → 依赖咒语 | L2（做事习惯） |

## 3 · 决策流程：遇到三类工程问题怎么查

```text
① "colcon build 报 undefined reference"
   先确认是不是跨包依赖：target_link_libraries + ament_export 齐了吗？
   再用 nm -C 查你想要的符号到底在不在此库：nm -C libmylib.so | grep 函数名
   （缺符号/没导出/命名空间错 ← 都能用 nm 一眼定位）

② "插件加载失败：Failed to load library / symbol not found"
   查注册宏与插件描述名一致；
   dlsym 找不到 = 类没导出（-fvisibility=hidden 时忘加导出宏）或名字修饰不匹配

③ "两个包对不上 / 行为诡异"
   先怀疑 ABI 不一致（版本混装）→ 统一发行版 + 编译器 + 全量重编
   再怀疑跨 .so 的 ODR（1.2）
```

## 4 · 常见坑（AI / 初学者代码高频）

| 坑 | 症状/原因 | 修法 |
| --- | --- | --- |
| 头文件里有普通函数/全局变量定义 | 链接/加载时符号冲突（A1 原样复发） | inline / 匿名 namespace / 移进 .cpp |
| `-fvisibility=hidden` 忘了给插件类导出宏 | dlopen 后 dlsym 找不到 | 导出宏包接口类与注册函数 |
| 跨发行版混合依赖 | ODR/布局错乱 | 统一发行版 + 同编译器全量重编 |
| 插件描述 xml 名字与注册宏不一致 | 加载时报名字不匹配 | 三处名字保持一致（xml/注册宏/类名） |
| 忘了 export include | 别的包 include 不到 | `ament_export_include_directories` |
| 静态库重复链入 | multiple definition | 尽量动态库；静态库每个依赖只链一次 |
| 用 dlopen 的库有全局静态对象 | 加载史前构造/卸载后析构顺序问题（T2） | 少用；惰性初始化 |

## 5 · 实践关联（动手清单）

```bash
# ① 用 nm 查"符号到底有没有、名字对不对"（06/08 的技能直接复用）
g++ -std=c++17 -shared -fPIC -x c++ -o libdemo.so - <<'EOF'
#include <cstdio>
extern "C" void plugin_entry(){ std::printf("plugin\n"); }  // 导出 C 符号
EOF
nm -D libdemo.so | grep plugin   # → T plugin_entry（动态符号表可见）

# ② 复现"符号没导出"：-fvisibility=hidden 后普通类默认不可见
#    注意：成员函数必须是类外定义（非内联）才会真生成符号
g++ -std=c++17 -shared -fPIC -fvisibility=hidden -x c++ -o libhide.so - <<'EOF'
struct Hidden { void f(); };                       // 默认隐藏
struct __attribute__((visibility("default"))) Public { void g(); };
void Hidden::f(){}   void Public::g(){}
EOF
nm -D libhide.so | c++filt | grep -E "Public|Hidden"   # → 只有 Public::g() 可见

# ③ dlopen/dlsym 最小演示（对照 pluginlib 原理）
cat > /tmp/v2/plugmain.cpp <<'EOF'
#include <dlfcn.h>
#include <cstdio>
int main(){
  void* h = dlopen("./libdemo.so", RTLD_NOW);
  if(!h){ std::printf("load fail: %s\n", dlerror()); return 1; }
  auto f = (void(*)())dlsym(h, "plugin_entry");
  if(f) f(); else std::printf("sym fail: %s\n", dlerror());
  dlclose(h);
}
EOF
g++ -std=c++17 /tmp/v2/plugmain.cpp -ldl -o /tmp/v2/plugmain && cd /tmp/v2 && ./plugmain
# → plugin（成功加载并调用）

# ④（有 ROS2 环境时）建一个最小 ament 包 + pluginlib 插件走一遍
```

## 6 · 与全局的连接

- **A1 / T6**：本体系是"翻译单元公理在二进制层的延伸"——`inline`/符号/ODR 的答案在 .so 之间一个不差。
- **08**：符号表（nm）直接复用；ABI 铁律进 L1 记忆卡。
- **15**：ROS2 工程面；**12**：模板在导出时的实例化可见性（模板实例默认弱符号，跨 .so 合并规则同样适用）。

## 7 · 自测三问

- **判定**：`-fvisibility=hidden` 下，一个普通类被插件 dlopen 后为什么找不到？（符号默认不可见，dlsym 拿不到——需要导出宏）
- **预测**：两个 .so 里各有一个同名的非 inline 全局函数，加载两个库会发生什么？（符号冲突/互相覆盖——运行期 ODR，同 A1）
- **构造**：用 `nm -D` + `dlopen` 复现"插件加载失败"→"加导出宏后成功"的完整过程（本文件 5-①~③ 的素材）。
