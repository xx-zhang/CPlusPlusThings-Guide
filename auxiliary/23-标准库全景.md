## 1 · 工具类四件套（专家天天用，AI 常常不用）

| 工具 | 一句话用途 | 何时用 | 坑 |
| --- | --- | --- | --- |
| `std::optional<T>` | 「有值 / 无值」 | 函数可能没结果（查表未命中） | `value()` 会抛；`*p` 不检查；别用 `optional<T*>`（直接 `T*` 即可） |
| `std::variant<A,B>` | 类型安全 union（多选一） | 状态机、解析结果 | 访问必须 `visit`（不是 `switch` 那种直觉） |
| `std::any` | 任意类型擦除 | 极少数场景（配置传递） | 运行时类型错会抛；性能差；**能用模板/继承就别用** |
| `std::expected<T,E>`（C++23） | 「值 或 错误」 | 错误处理（见 09 §1.3 预期错误） | C++23 前用 `tl::expected` 或错误码 |

**专家判据**：**「可能没有」用 `optional`；「错误」用 `expected`/异常；「多选一」用 `variant`。** 不要用魔法值（`-1`、`nullptr`）表达这些语义。

## 2 · 字符串：三个必须分清的类型

```text
std::string        拥有字符，可改，堆分配（SSO 小串内联）
std::string_view   不拥有，只借用（A5 所有权三态之"借用"）——**不能超过被借对象生命周期**
const char*        C 风格，无长度，需 strlen 遍历
```

**专家规则**：**参数传 `string_view`（而非 `const string&`）**——因为 `const string&` 会强迫调用方构造临时 `string`；`string_view` 接受 `const char*`/`string`/字面量零拷贝。

```cpp
void log(std::string_view msg);        // ✅ 零拷贝
void log(const std::string& msg);      // ⚠️ 传字面量会构造临时 string
```

**坑**：`string_view` 指向临时对象 → 悬垂（同 01 的 T3 生命周期规则）。别从返回的临时 `string` 构造 `string_view` 存下来。

## 3 · ranges 与视图（C++20：写法和心智都变了）

```cpp
// 老写法
for (auto it = v.begin(); it != v.end(); ++it) if (*it > 0) out.push_back(*it * 2);

// ranges 写法
for (auto x : v | std::views::filter([](int i){return i>0;})
              | std::views::transform([](int i){return i*2;})) out.push_back(x);
```

**专家要点**：

- **视图是惰性的、不拥有数据**（同 `string_view` 的借用性质）——生命周期照旧是坑。
- 视图可组合（管道 `|`），但**别把视图存起来跨越原容器的修改**。
- `std::ranges::sort` 等算法 + `views` 一起用；`std::span` 做「连续内存的借用视图」（比 `T* + size` 安全）。

## 4 · type_traits 与编译期判断（读库源码的钥匙）

```text
最常用的一小组（记名字即可，签名现查）：
  is_same / is_integral / is_floating_point / is_pointer / is_reference
  is_constructible / is_convertible / is_copy_constructible / is_nothrow_move_constructible
  remove_reference / remove_cv / decay / common_type / conditional_t / enable_if_t
用法：static_assert(std::is_nothrow_move_constructible_v<T>, "容器要靠它走移动");
```

**专家判据**：`is_nothrow_move_constructible` **不是学术兴趣**——它决定 `vector` 扩容走移动还是拷贝（实测见 08：15 move/0 copy vs 15 copy）。**给自己的类型加 `noexcept` 移动就是靠这个被检出的。**

## 5 · 时间（chrono）：三个时钟必须分清

| 时钟 | 单调？ | 用途 | 坑 |
| --- | --- | --- | --- |
| `steady_clock` | ✅ 单调 | **测时（性能/超时）** | —— |
| `system_clock` | ❌ 可被 NTP 调整 | 墙上时间（日志时间戳） | 用它测时间会得到负数/跳变 |
| `high_resolution_clock` | 实现定义（常是前面之一） | 一般测量 | 别假设它单调 |

```text
专家规则：**测耗时/算超时用 steady_clock**；打日志/对外显示用 system_clock。
ROS2 还有第三层：ROS 时间/仿真时间（见 18）。
```

**坑**：`duration_cast` 丢精度；`sleep_for` 不保证精确唤醒（只保证不早于）。

## 6 · filesystem：错误处理有两个版本（专家细节）

```cpp
std::filesystem::exists(p);            // 抛异常版本
std::error_code ec;
std::filesystem::exists(p, ec);        // 不抛版本 ← 热路径/无异常项目用这个
```

**这正是 09 §1.3 的「预期错误 vs 异常错误」在库里的落地**：IO 失败是**预期错误**，所以标准库给了两个重载。

## 7 · 内存与分配（pmr：性能敏感场景的武器）

```text
std::allocator<T>              默认分配器（容器模板参数，少见但要知道）
std::pmr::*（C++17）           多态分配器：monotonic_buffer_resource（只增不释放，超快）
pmr::vector<T>                 把分配策略从**类型**变成**运行时对象** → 同一容器可换策略
std::align / alignas           对齐（见 13 §1.2）
std::launder / construct_at    对象生命周期层面的原语（placement new 的正规写法）
```

**专家判据**：**热路径大量小分配**（具身智能常见）→ 先 `reserve`，再考虑 `pmr::monotonic_buffer_resource` 或自建池（见 18 §1.1）。

## 8 · 数值与随机（别再用 rand()）

```text
<random>：mt19937 / pcg / uniform_int_distribution —— **rand() 不要用**（质量差、范围错、不可复现控制）
<numbers>（C++20）：std::numbers::pi 等常量，替代 M_PI
<charconv>（C++17）：to_chars/from_chars —— **比 stringstream 快一个量级、无本地化、不抛**
```

**专家判据**：解析数字用 `from_chars`（性能敏感/无异常）；格式化数字用 `to_chars` 或 `std::format`。

## 9 · 格式化与输出

```text
printf 家族       C 风格；类型不安全；但快、无分配（嵌入式常用）
iostream          C++ 风格；类型安全；但慢（同步、虚调用、locale）
std::format(20)   ✅ 首选：类型安全 + 范围检查 + 类 printf 语法；{fmt} 是其原型
std::print(23)    直接输出到 stdout
```

**专家规则**：日志/热路径**不要用 `iostream`**（慢且会分配）；`std::format` 优先；嵌入式用 `printf` 或自研轻量格式化（见 18 §1.1）。

## 10 · 决策表：我要做 X，用 Y

| 我要…… | 用 | 不要用 |
| --- | --- | --- |
| 只读传一段字符串 | `std::string_view` | `const std::string&` |
| 只读传一段连续内存 | `std::span<T>` | `T* + size` |
| 表达「可能没有值」 | `optional<T>` | 魔法值 / 裸指针 |
| 表达「值或错误」 | `expected<T,E>`（C++23）/ `error_code` | 抛异常（若是预期错误，见 09） |
| 表达「多选一」 | `variant<A,B>` | union + tag / 继承 |
| 测耗时 | `steady_clock` | `system_clock` |
| 解析数字 | `from_chars` | `stringstream` / `atoi` |
| 生成随机数 | `<random>` 引擎 + 分布 | `rand()` |
| 格式化输出 | `std::format` | `iostream`（热路径）/ `sprintf` |
| 惰性数据处理链 | `views::filter/transform` | 手写循环 + 中间容器 |
| 大量小分配 | `reserve` / `pmr` / 池 | 逐个 `new` |

## 12 · 自测三问

- **判定**：函数参数该用 `const std::string&` 还是 `std::string_view`？为什么？（`string_view`——避免字面量构造临时 `string`；但注意生命周期）
- **预测**：`std::vector<T>` 扩容时，`T` 的哪个 trait 决定走移动还是拷贝？（`is_nothrow_move_constructible`——实测见 08）
- **构造**：写同一段"过滤+变换"的代码，分别用老式循环、`<algorithm>`、`ranges::views` 三种写法，比较可读性与是否产生中间容器（用分配计数验证）。
