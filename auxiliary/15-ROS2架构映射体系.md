## 0 · 先建立坐标系：ROS2 是这样一层叠一层的

```text
┌──────────────────────────────────────────────────────────────┐
│ 应用层：节点(Node) · 话题(话题/服务/动作/参数/时钟) · 生命周期   │   ← 你写的 C++ 在这
├──────────────────────────────────────────────────────────────┤
│ rclcpp：执行器(Executor) · 回调(Callback) · 回调组 · QoS API   │   ← 并发模型在这（17）
├──────────────────────────────────────────────────────────────┤
│ rcl：图/名字/时钟/参数/错误处理（与语言无关的抽象）              │   ← 较少写，但要知道
├──────────────────────────────────────────────────────────────┤
│ rmw：中间件抽象层 · intra-process 零拷贝 · loaned message      │   ← 性能在这（18）
├──────────────────────────────────────────────────────────────┤
│ DDS（Fast DDS / Cyclone DDS）：发现/可靠性/持久性/传输          │   ← 架构知识（L3 现查）
└──────────────────────────────────────────────────────────────┘
```

**关键认知**：ROS2 的 C++ 编程 = **回调驱动 + 共享所有权 + 分布式消息**。它不是"你自己开线程"，而是「**执行器调度回调**」模型——这决定了下面要补的一系列知识。

## 2 · 两个必懂的 ROS2 编程范式（先记住，细节在对应体系）

### 2.1 一切皆共享指针 + 回调（典型的"所有权 + 事件驱动"）

```cpp
// 伪代码：典型 ROS2 节点片段
class MyNode : public rclcpp::Node {            // Node 继承 enable_shared_from_this
public:
  MyNode() : rclcpp::Node("my_node") {
    sub_ = this->create_subscription<Msg>(
      "topic", 10, [this](const Msg::SharedPtr msg){ on_msg(msg); });   // 回调
  }
private:
  void on_msg(const Msg::SharedPtr msg) { /* 别在这里做阻塞/分配 */ }
  rclcpp::Subscription<Msg>::SharedPtr sub_;
};
// 生命周期：必须 make_shared<MyNode> 创建，再交给 executor（16）
```

**三个立刻要懂的 C++ 事实**（都来自已有公理）：

1. `Msg::SharedPtr` = `shared_ptr<const Msg>`——**共享所有权**，消息可以跨线程传递（16）。
2. 回调在 executor 线程里执行——**它不是你自己开的线程**（17）。
3. 回调里做序列化/分配/阻塞 = 饿死自己节点 + jitter（17/18）。

### 2.2 执行器 = 协作式调度（决定你代码怎么写）

```text
SingleThreadedExecutor   ：一个线程跑所有回调（顺序=就绪顺序）
MultiThreadedExecutor    ：多线程并发跑回调；回调组控制"哪些能并行"
StaticSingleThreadedExecutor：半静态，减少锁

CallbackGroup 两型（官方语义，已核实）：
  互斥 Mutually Exclusive ：组内回调绝不并发（默认）
  可重入 Reentrant        ：组内回调可与自己并发，也可与其它组并发
```

**推论（规则级，务必背）**：

- 单线程 executor 里，一个回调阻塞/长任务 ⟹ **其它回调全被饿死**。
- 回调里 `spin`/同步等待服务结果 ⟹ 当场死锁（经典错误）。
- 默认互斥回调组 ⟹ 重负载也不并行（想并行要显式 reentrant 组）。

## 3 · QoS 速查（L3 现查 + 语义要点）

> QoS = 对「这条消息链路的期望」的声明。三根轴（记住三轴，数值现查）：

| 轴 | 选项 | 何时选 |
| --- | --- | --- |
| **Reliability** | `RELIABLE` / `BEST_EFFORT` | 控制类要可靠；海量点云/图像可 best-effort（丢帧可接受） |
| **Durability** | `VOLATILE` / `TRANSIENT_LOCAL` | 要不要让"后加入的订阅者"收到旧数据（如静态地图/latched） |
| **History** | `KEEP_LAST(n)` / `KEEP_ALL` | 缓冲多少条；KEEP_LAST 默认 10（注意匹配 QoSPolicyCompatibility） |

**C++ 联系**：用 `rclcpp::QoS(10)` 或 `QoS(n).reliable().transient_local()` 配置；不给它配就用 `SystemDefaultsQoS`。
