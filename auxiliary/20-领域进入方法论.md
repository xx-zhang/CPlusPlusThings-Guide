# 20 · 领域进入方法论（v2：从「描述系统」到「解释并跟进系统」）

> **来源**：本文件整合了**学习者对 `00` §6「生活/工作延申」的批判**（2026-09）。
> **原版的问题**（原话）：*「它描述系统，但不一定解释系统为什么这样运行，也不保证你能跟进对。」*
> **最尖锐的一条**：原版把 C++ 框架三源中的 **γ 源（可观测仪器）** 弄丢了——只搬了「本体/规则」和「设计动机」，于是**没有反馈、无法自验**。本版补回。
>
> **用法**：进入一个**新领域 / 新组织 / 新系统**时用本版（七层 + 五问 + 三补 + 一闭环）；只是快速过一遍代码或一次会议，用 `00` §6 的轻量四问即可。

---

## 0 · 原版缺什么（批判清单 → 本版补法）

| # | 缺口 | 后果（为什么会「不保证跟进对」） | 本版补法 |
| --- | --- | --- | --- |
| 1 | **目标 / 价值** | 没有目标，实体和规则**没有优先级**，你会平均用力 | §1 第 1 层「目标」；§3 三补之一 |
| 2 | **激励 / 权力 / 利益** | 规则**会被绕过**；你不知道谁解释、谁受益、谁受损 | §1 第 3 层；§3 三补之二 |
| 3 | **反馈 / 度量 / 演化** | **无法知道自己理解对不对**（γ 源缺失的直接后果） | §1 第 7 层；§3 三补之三；§4 闭环 |
| 4 | **外部环境与边界** | 领域不是封闭系统：监管、市场、对手、技术会**改写规则** | §1 第 3 层内嵌「外部约束」；§2 通道问 |
| 5 | **概率 / 成本 / 不确定性** | 「锁死 vs 现场定」**不是二选一**，是成本×可逆性×信息完备度的权衡 | §1 第 5 层；§2 时机问的判据表 |
| 6 | **「未规定」≠「无规则」** | 未规定区会被**惯例 / 权力 / 默认配置 / 裁量权**填充；不问清楚，出事就没人认账 | §1 第 3 层；§2 规则问必答「谁解释 / 谁兜底 / 按什么判」 |
| 7 | **编号顺序与认知顺序不一致** | 原版 ①→A3、②→A2、③→A1，**倒着跳**，纯增加记忆负担 | §1 按**认知顺序**重排；编号顺序另作说明（见 §1 末注） |

## 1 · 七层阶梯（补全版顺序）

> 顺序按**认知顺序**（一个外来者进入陌生领域的自然次序），不按 C++ 公理编号。

| 层 | 要回答的问题 | C++ 对应 | 产出的工件 |
| --- | --- | --- | --- |
| **1 目标** | 为谁解决什么问题？成功怎么度量？成本/风险/体验怎么权衡？ | 设计决策 D · 元原则 | 目标声明 + 成功指标 |
| **2 世界 / 本体** | 真实存在的实体是什么？（人 / 钱 / 状态 / 接口 / 约束） | **A3** 对象模型 | 实体清单 + 状态图 |
| **3 规则 / 制度** | 允许怎样变？禁止什么？**未规定谁解释？越界后果？谁有解释权？** 外部约束（监管/市场/对手）是什么？ | **A2** 语义（UB = 未规定） | 规则边界表 + **未规定区清单** |
| **4 通道 / 认识** | 信息源头在哪？我看到的是全貌还是**局部**？延迟与失真在哪？ | **A1** 翻译单元 | 信息流图 + 失真点 |
| **5 时机 / 决策** | 哪些**不可逆必须锁死**？哪些可逆可现场定？谁有权？**成本/可逆性/信息完备度**如何权衡？ | **A4** 分层（何时决定） | 决策点表（锁死 / 现场）+ 授权矩阵 |
| **6 责任 / 失败** | 失败路径谁收尾？有没有**强制**？升级链是什么？ | **A5** 资源（析构必被调） | 兜底责任 + 升级链（RACI/SOP） |
| **7 反馈 / 演化** | 指标是什么？异常怎么暴露？事故怎么复盘？规则怎么更新？ | **γ 源** + 实测闭环 | 监控指标 + 复盘机制 + 规则变更流程 |

**关键认知（回答「为什么不按 A1…A5 编号」）**：

```text
A 编号的顺序 = 程序的"生命周期顺序"：翻译(A1) → 语义(A2) → 世界(A3) → 时机(A4) → 资源(A5)
认知的顺序   = 观察者"进入陌生领域"的顺序：目标 → 有什么 → 怎么变 → 我怎么知道 → 何时定 → 谁兜底 → 怎么纠错
两套顺序服务不同目的：**学 C++ 用 A 顺序（跟着程序生命周期走），进新领域用认知顺序**。
把它们混用（原版那样 ①→A3 ②→A2 ③→A1）只会增加记忆负担 —— 这就是那条批评的准确之处。
```

## 2 · 五问（每层的最小提问，必答）

```text
① 实体：人、钱、状态、接口、约束分别是什么？谁掌握它们？
② 规则：允许什么变化？禁止什么？**未规定谁解释？越界后果？** 外部约束有哪些？
③ 通道：信息源头在哪？我看到的是全貌还是"翻译单元"？延迟和失真在哪？
④ 时机：哪些不可逆必须锁死？哪些可逆可现场定？谁有权？
           —— 判据不是二选一，而是问四件事：
              成本（错了多贵？）× 可逆性（能回退吗？）× 信息完备度（现在够判断吗？）× 决策速度价值
⑤ 失败：失败路径谁收尾？有没有强制？升级链是什么？（无强制的规则 = 建议，不是规则）
```

> **第 ②问的加粗部分是本版与原版最大的行为差别**：原版止于「有没有规定」；本版必须追到**「未规定区由谁填充」**。因为组织里的「UB」不会真的空着——它由惯例、权力、默认配置、裁量权填充，只是**没写明**。

## 3 · 三补（原版最致命的缺口）

| 补什么 | 关键提问 | 为什么缺了它就不行 |
| --- | --- | --- |
| **目标** | 为谁解决什么问题？成功度量是什么？ | 没有目标 → 无法给实体/规则排优先级 → 平均用力 |
| **激励** | 谁受益、谁受损？谁有动力遵守、谁有动力绕过？谁有解释权？ | 不处理激励 → 规则会被绕过，你的模型会持续预测失败 |
| **反馈** | 指标是什么？审计/事故复盘怎么做？规则怎么更新？ | 没有反馈 → **无法知道自己理解对不对**（= 丢了 γ 源） |

## 4 · 检验标准：一个理解是否「合理」（8 条）

**判断标准（不看自洽，看能否）**：

| # | 标准 | 问法 | C++ 侧的对应 |
| --- | --- | --- | --- |
| 1 | **预测** | 给定变化，能预测结果和副作用吗？ | 从公理推变体（T 系列） |
| 2 | **解释** | 历史事故、异常、冲突能被解释吗？ | 01 的多路径互证 |
| 3 | **定位** | 问题出在实体 / 规则 / 通道 / 时机 / 责任哪一层？ | 07 场景速查表 |
| 4 | **行动** | 知道找谁、看什么、改什么、何时锁死？ | 各体系的决策流程 |
| 5 | **抗反例** | 遇到异常能**修正模型**，而不是硬套？ | 08 反例档案 |
| 6 | **闭环** | 有指标和反馈，错误能暴露并纠正？ | **实测（六步法的③）** |
| 7 | **共识** | 不同角色对边界、责任、信息源的描述**一致**吗？ | 02 术语表（同一名字同一含义） |
| 8 | **落地** | 能产出状态机、接口契约、RACI、SOP、监控、演练吗？ | 可编译/可测试的代码 |

> **第 7 条最容易被忽略**：如果两个角色对「谁负责」的描述不一致，那**不是理解不够深，是理解压根不对**。

## 5 · 跟进方法（七步走）

```text
1. 写目标：为谁、解决什么、成功度量（基线 + 目标值）
2. 画实体状态图：实体、状态、资源、接口、约束
3. 列规则边界 + **未规定区清单**（每条未规定：谁解释 / 谁兜底 / 按什么判）
4. 画信息流与"翻译单元"：源头、我看到的部分、延迟与失真点
5. 标决策点：锁死 vs 现场定（用 §2 ④的四项判据），配授权矩阵
6. 定失败责任与强制机制：兜底人、升级链、无强制的项标"建议"
7. 加目标指标 + 激励 + 反馈：监控、复盘、规则更新；**小规模试点 → 复盘 → 修正模型**
```

> 第 7 步是原版完全没有的，也是本版的核心修补：**先试点、再复盘、再改规则**——这就是 γ 源在组织里的形态。

## 6 · 何时用哪版（别为了「全」而每次都跑七层）

| 场景 | 用哪版 | 成本 |
| --- | --- | --- |
| 读一段代码 / 审一个 PR / 开一次会 | `00` §6 轻量四问 | ~2 分钟 |
| 进入新领域 / 新组织 / 新系统 / 新项目 | **本文件**（七层 + 五问 + 三补 + 8 条检验 + 七步） | ~1 小时起 |
| 已经熟悉、只需查漏 | 跳过 1-2 层，重点看「未规定区」和「反馈」 | ~10 分钟 |

> 这本身就是元原则 1（零开销抽象）的迁移：**不用不付费**。为一次代码审查跑七层，是新的教条主义。

## 7 · 为什么这不是「另一套东西」：与 C++ 框架的同构表

| 领域进入层 | C++ 公理/源 | 同构的意思 |
| --- | --- | --- |
| 1 目标 | D1–D5 设计决策 · 元原则 | 都回答「为什么要这样」 |
| 2 世界 | **A3** 对象模型 | 都回答「有什么」 |
| 3 规则 | **A2** 语义（UB = 未规定） | 都回答「允许怎样变、越界怎样」 |
| 4 通道 | **A1** 翻译单元 | 都回答「我看见的是不是局部」 |
| 5 时机 | **A4** 分层 | 都回答「何时决定」 |
| 6 责任 | **A5** 资源 | 都回答「谁收尾、有无强制」 |
| 7 反馈 | **γ 源**（仪器/实测/反例） | 都回答「我怎么知道我对」 |

**结论**：七层不是新发明，是把 C++ 框架的**三源结构**（α 模型 / β 动机 / **γ 仪器**）完整地搬到组织与流程上。原版丢掉 γ，本版补回——**这就是这次批判的全部价值**。
